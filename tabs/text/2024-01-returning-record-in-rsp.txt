Returning IIS Patient Immunization
Record Information in a Z32 and Z42
RSP

Executive Summary

This TAB reviews expectations for IIS for return of patient and immunization record
information in a Z32 and Z42 response message, indicating information that
shall/should/may/should not/shall not be returned, when a single patient match is found in
response to a query request. For example, an IIS shall return ‘completed’ immunizations
but shall not return ‘deleted’ immunizations. Updated Z32 and Z42 RSP specifications are
provided in alignment with the return expectations.

Background

The National IG reviews the goals of the Z32 and Z42 RSP message, with the Z32 aiming to
return a complete immunization history and the Z42 aiming to return an evaluated
immunization history and forecast. Since the focus of a Z42 is on returning an evaluated
immunization history and forecast, per the National IG, it is “not intended to return all the
details expected of a complete immunization history.” On the other hand, in reviewing
capabilities of IIS as responding systems, the IIS Functional Guide, Volume 1: Query and
Response does not differentiate between the Z32 and Z42 RSP, indicating that, regardless of
the query profile, IIS should “return as much data as the Responding System is allowed to
return per local policy and to always include the clinical decision support (i.e., evaluation
and forecast).”

An additional AIRA guidance document, Security Guidance Considerations for Immunization
Information Systems, indicates that IIS should “return only what is minimally necessary” in a
response message when a single patient match is found and “never send back information
like Social Security number, mother’s maiden name, or an alternative/potential address
located in the IIS.”

This TAB seeks to harmonize and clarify guidance for IIS for return of patient and
immunization information in Z32 and Z42 RSP messages.

Implications

Although IIS are population-based databases, it is not always the case that all information
known to an IIS about a given patient’s demographic information needs to be returned in a
Z32 or Z42 response message, per the tables above. IIS are not intended to serve as
repositories of current patient identifying information; therefore, jurisdictions may choose
whether to return certain information. For example, regardless of whether the IIS stores
the information contained in the PD1 segment, the NK1 segment, and PID fields (including
those conveying the patient’s race, ethnic group, address, and phone number/email
address), a jurisdiction may choose whether or not to return this information in a Z32 and
Z42 RSP per the updated specifications.

On the other hand, when the IIS contains information about the patient’s immunization
history, it is generally expected that this information will be returned in a Z32 or Z42 RSP.
The updated specifications clarify that completed immunizations shall be returned and
partial administrations should be returned with the action code (RXA-21) value ‘A’. When
immunization events are returned, population of the RXA-9 field, immunization information
source, is optional, as this field is defined in the context of a VXU but not in the context of
an RSP. Finally, when a completed or partial immunization is returned, information
associated with the vaccination event (e.g., administering provider, lot number, expiration
date, administered-at location, manufacturer name, and ordering provider) shall be
returned if known.

indicated, it follows that an IIS shall have the information available to return, as the
