Additional “Unknown” Race and
Ethnicity Codes

Executive Summary

An extension of the CDCREC value set is indicated, with additional codes to represent
unknown race and/or ethnicity:

    • UNK – Unknown
    • ASKU – Asked but unknown
    • PHC1175 – Refused to answer
Submitting systems MAY submit these codes in a VXU to represent an unknown race and/or
an unknown ethnicity, as appropriate. Receiving systems SHOULD process these codes and
MAY translate to another value representing a similar concept for storage/saving.
Additionally, receiving systems SHALL process VXU messages with or without valid race
and/or ethnicity codes, unless prohibited by law or policy.

Background

Per the National IG, an unknown/undetermined patient race or ethnic group may be
indicated by leaving the PID-10 or PID-22 field blank, respectively. The CDCREC value set,
from which the patient race and ethnic group codes are sourced, does not include code(s)
to indicate the concept of an “unknown” value.
Some immunization information systems (IIS) have extended the value set to include
additional code(s) to represent an unknown value. Codes representing the concept of an
“unknown” or null value are found in the Fast Healthcare Interoperability Resources (FHIR)
NullFlavor Value Set and the Public Health Information Network Vocabulary Access and
Distribution System (PHIN VADS) Race Category including Null Flavor Value Set.
This TAB aims to provide interim guidance on the use of additional codes that represent an
unknown race and/or ethnic group in immunization messaging. This information may be
superseded as new national guidance from the CDC, HL7 International, and/or the ONC is
introduced, as this is an area under active discussion.

Scope

In scope
Extension of the CDCREC value set to include additional codes to represent unknown race
and unknown ethnic group. Conformance expectations for submission and processing of
the additional “unknown” codes.

Out of scope
Conformance expectations for receiving systems to save/store the additional unknown
codes or to return these codes in response to a query message.

Clarifications and Conformance Expectations

The additional codes representing unknown race and ethnicity and corresponding
conformance expectations are provided in Tables 1 and 2 below, respectively. Clarification
is also provided on processing a vaccination update (VXU) message when an invalid (i.e.,
not recognized) code is submitted.

Additional “unknown” race codes
Table 1 indicates three additional codes to represent unknown race. In a VXU message,
patient race is reported in PID-10, with PID-10.1 indicating the code, PID-10.2 indicating the
human-readable text associated with the code, and PID-10.3 indicating the value set
identifier. The value set identifier for the codes in Table 1 SHALL be “CDCREC.”

Table 2 indicates three additional codes to represent unknown ethnic group. In a VXU
message, patient ethnic group is reported in PID-22, with PID-22.1 indicating the code, PID-

Processing a VXU with an unknown patient race and/or ethnic group
HL7 v2 processing rules indicate that, if the value in a field is invalid (i.e., unknown to the
receiving system), the receiving system SHALL raise an error but SHALL continue to process
the message as if the field were not valued. Except where prohibited by law or policy:

   • Receiving systems SHALL process VXU messages with or without valid race and
       ethnicity codes. For example, if a receiving system does not recognize the code
       submitted, the system SHALL continue to process the message as if the field were
       not valued.
