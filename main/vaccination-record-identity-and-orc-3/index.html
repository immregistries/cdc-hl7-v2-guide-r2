4.6.3 Vaccination Record Identity and ORC-3

ORC-3 carries the identifier used to refer to a vaccination record across messages. In an inbound VXU, the value normally identifies the submitting system’s vaccination record and supports later correction or deletion. The submitting system maintains this identifier for the lifecycle of the source record.

An IIS does not necessarily preserve each submitted vaccination as a separate event. It may match duplicate reports, combine information received from multiple sources, or otherwise maintain one consolidated vaccination event associated with several source records. The identifier assigned by the IIS to the consolidated event and an identifier assigned by a submitting system to its source record identify related but different objects.

Retaining an association between the submitting source, its ORC-3, and the consolidated event can improve correction and query-response workflows. The association can help the IIS locate the appropriate source record when processing an update or delete. It can also provide a querying system with additional information for distinguishing vaccinations it previously reported from vaccinations reported by other sources.

This information is useful but does not address an acute interoperability failure. Querying systems have operated for years without consistent return of source-assigned ORC-3 values and commonly use other information to reconcile returned vaccination histories. The requirements below therefore establish a preferred direction while recognizing that many current IIS do not yet retain the source-to-event associations needed to implement it reliably.

When a reliable source-specific association is available and the IIS can determine that the querying system represents the source that assigned the identifier, returning that source-assigned ORC-3 is preferred. When the association is unavailable, the IIS can return an identifier assigned to the consolidated vaccination event. The assigning authority associated with ORC-3 is essential to distinguishing which organization is responsible for the identifier. An identifier assigned by one source is not interchangeable with an identifier assigned by another source or by the IIS.

Conformance statements

  1. SHOULDIIS SHOULD retain a durable association between the submitting source, the source-assigned ORC-3, and the consolidated vaccination event.s1
  2. SHOULDWhen responding to the same source, IIS SHOULD return the source-assigned ORC-3 when the association is reliably available.s2
  3. MAYWhen a source-assigned ORC-3 is not reliably available, IIS MAY return an IIS-assigned identifier for the consolidated vaccination event.s3
