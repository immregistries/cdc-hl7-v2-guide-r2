3.5.2.1 Z23 - Return an Acknowledgement

Quality review 3 warnings · 2 notes

Findings from automated and editorial checks, for the authors. Not part of the guide.

  • Warning SISC guidance Guidance for HL7 RSP Messages to Support Interoperability (Query Response Guidance (message is rejected)): Partly covered. The guide's Z23 section describes the same outcome more broadly ("malformed or invalid MSH/QPD segments, missing required message header information, or other unrecoverable errors detected prior to query execution"), and figure 17 shows it as "Structurally valid? No". It does not name the four MSH conditions. The fifth condition, "unrelated to format or content", is one the guide removes as a reason for 'AR' on a VXU (following the ACK TAB), because it describes a transport problem. The guide does not say whether it is also removed for queries.
    Partly coveredAction: Narrative
    Guidance The message is rejected when it has an unsupported message type or event code (MSH-9), an unsupported processing ID (MSH-11), or an unsupported version ID (MSH-12), or cannot be processed for reasons unrelated to format or content. The Z23 (ACK) profile is the response.
    Recommendation Name the MSH conditions that lead to a Z23, and say that, as for VXUs, a transport or connectivity problem is never reported with a Z23.

    See the SISC guidance comparison

  • Warning SISC guidance Guidance for HL7 RSP Messages to Support Interoperability (Query Response Guidance (message is rejected)): Missing. The Z23 section says the IIS "is unable to execute the query" but not what MSA-1 and ERR-4 contain. The guide's MSA-1 rules ('AR' when there is a severity 'E' error) are written for a VXU ("SHALL be returned to convey VXU rejection"). The IGAMT Z23 profile allows either a Q11 or a V04 trigger, so the same profile serves both, but only the VXU case is described.
    MissingAction: Narrative
    Guidance In a Z23 sent in response to a query, MSA-1 must be AR, an ERR segment must be present, and ERR-4 must be E (the sender should correct the issue and resubmit).
    Recommendation In the Z23 section, state that a Z23 sent in response to a QBP has MSA-1 'AR' and one ERR segment with ERR-4 'E'.

  • Warning TA question (MSH Message Header, MSH-21 Message Profile Identifier): Differs. Asked in 2019 and 2020 and answered: return a Z33 RSP, not a Z23. The guide now says a query that cannot be processed (malformed MSH or QPD, missing required header information) gets a Z23 ACK, and IGAMT allows MSH-9.2 'Q11' in the Z23 profile. Systems built to the past answer will send and expect Z33.
    Differs

    Recommendation Confirm the change, record it in the change history, and say which query errors get a Z23 ACK and which a Z33 RSP (for example, an invalid QPD parameter). Z23 is also listed under the RSP profiles, though it is an ACK; say so.

    qf-ta-q30-015

A Z23 response indicates that the query message could not be processed due to a structural or application-level problem detected within the HL7 message itself, for example, malformed or invalid MSH/QPD segments, missing required message header information, or other unrecoverable errors detected prior to query execution. In this case, the IIS is unable to execute the query as requested, and no patient matching or record retrieval is performed.

Consistent with the Application-Level Scope of ACK Messages described in the Acknowledgement Message Profile section, a Z23 response represents an application-level outcome and is distinct from transport or connectivity failures (such as SOAP faults, network issues, or authentication failures), which are handled at the transport layer and are never conveyed through an ACK or RSP.

Z23 responses are not part of normal query processing and generally indicate a configuration or message-construction error that must be corrected before successful queries can occur. Implementers should treat a Z23 as a signal to correct the submitted message (header or structure) and retry.
