4.3.3 Open Value Sets (Extensible Sets Supporting Local Variation)

Open value sets permit local extension by trading partner agreement. These sets are used where jurisdictions may require additional specificity beyond nationally defined values, or where the domain is inherently variable. Open extensibility does not eliminate national expectations; rather, it allows additional values to coexist with them.

Open value sets are common in demographic and contextual data, where local programs may capture more detailed information while still supporting national interoperability. Examples include race, ethnicity, and language.

Systems (including IIS and submitting/receiving systems) MAY accept locally extended values for open valuesets. Systems SHALL recognize and correctly process nationally defined values even when local extensions are supported. When an unrecognized value for an open value set is received, the receiving system SHOULD generate an informational or warning response to notify the sender rather than an error, particularly for fields with usage RE, or O. Receiving systems SHALL document and communicate their chosen handling approach to trading partners during onboarding and SHALL avoid excessive, non-actionable notifications where operationally appropriate. Submitting systems SHALL use nationally defined values when applicable before in introducing local extensions.
