3.5.2.4 Z33 - Return a Response with No Person Records

Quality review 4 warnings · 2 notes

Findings from automated and editorial checks, for the authors and reviewers. Not part of the guide.

  • Warning Example Example "Consent/Disclosure Restriction Flow (Z44 → Z33)" (message 1): MSH-4 (Sending Facility) is required in MSH_#ConsolidatedIG_IZ01 but empty.qf-example-required-42732c7b
  • Warning SISC guidance Query Responses and Patient Protection (Guidance when implementing Release 1.5): Missing. The guide has a single Z33 for every case and no way to tell a querying system that a protected patient was found. The FAQ records why that matters: EHR systems may need to distinguish a protected patient from no patient (for example, so staff do not create a duplicate record or keep re-querying).
    MissingAction: Narrative
    Guidance Where law and policy do not strictly prohibit indicating that the patient exists, send a modified Z33: MSA-1 'AA'; ERR-3 populated (207, Application Internal Error, suggested); ERR-4 'I' (the querying system is not expected to fix or resend anything); ERR-5 empty; ERR-8 text saying a patient was found but is protected (for example, "A match was found in the IIS but no value is returned since Data Sharing for the record is set to No"); QAK-2 'NF'.
    Recommendation Describe the "protected patient found" Z33 in the Z33 section, updated for this guide: MSA-1 'AA', one ERR segment with ERR-4 'I' and ERR-5 2700 (see sisc-qrpp-05), ERR-8 text for the user, and QAK-2 'NF' (or 'PD'; see sisc-qrpp-06). State that an IIS uses it only where law and policy allow it to reveal that the patient exists.

    See the SISC guidance comparison

    qf-sisc-qrpp-04
  • Warning SISC guidance Query Responses and Patient Protection (Guidance for incorporation into a future release): Missing. Neither the guide nor IGAMT has 'PD': QAK-2 is bound to HL70208_IZ01 with OK, NF, TM, AE, and AR. 'PD' is not an HL7 v2.5.1 code, so adding it would extend an HL7 table. With ERR-5 2700 available, 'PD' may no longer be needed, but the FAQ said it would be added, so its omission should be a decision rather than an oversight.
    MissingAction: CDC decision
    Guidance In the next release, QAK-2 is 'PD' (Protected Data), a new code used when a protected patient is found.
    Recommendation CDC to decide whether to add QAK-2 'PD' or rely on QAK-2 'NF' with ERR-5 2700. Record the decision in the change history.

    See the SISC guidance comparison

    qf-sisc-qrpp-06
  • Warning SISC guidance Guidance for HL7 RSP Messages to Support Interoperability (Query Response Guidance (error prevents the query)): Missing. The guide's Z33 section lists only no match, policy limits, and consent restrictions, and says that a Z33 means the IIS "has processed the query". Figure 17 has no path for a query that is accepted but cannot be executed. The combination this guidance requires also conflicts with the guide's new ACK model: for a VXU the guide says MSA-1 'AE' SHALL NOT be returned with a severity 'E' error, and that 'AE' means a qualified acceptance. If that model applies to query responses, a failed query would get MSA-1 'AR'; if it does not, the guide needs to say so.
    MissingAction: CDC decision
    Guidance When the message is accepted but an error prevents the query from being executed, the response is a Z33 with MSA-1 'AE', QAK-2 'AE', and ERR-4 'E'. QAK-2 may not be AR (reserved for the Z23 conditions) or OK, TM, or NF (which report a query that was executed).
    Recommendation CDC to decide how a query that cannot be executed is reported: Z33 with MSA-1 'AE' as in this guidance, or Z33 (or Z23) with MSA-1 'AR' to match the ACK model. Then add the outcome to the Z33 section and to figure 17, with the QAK-2 value ('AE').

    See the SISC guidance comparison

    qf-sisc-rsp-06
  • Note SISC guidance Guidance for HL7 RSP Messages to Support Interoperability (Caveats; Summary): Partly covered. The IGAMT RSP profiles allow ERR [0..1], as the base standard requires, so the limit is enforced. The narrative never mentions it, or says which error to return when there are several. Readers who know the ACK (which allows many ERR segments) will not expect the difference.
    Partly coveredAction: Narrative
    Guidance An RSP^K11 message may contain only a single ERR segment. When several errors are found, the responding system selects the most salient one to return.
    Recommendation Add a sentence to the RSP profile sections: an RSP carries at most one ERR segment, so the IIS returns the most significant issue.

    See the SISC guidance comparison

    qf-sisc-rsp-02
  • Note TAB Returning IIS Patient Immunization Record Information in a Z32 and Z42 RSP (Table 1: Patient types): Partly covered. The guide says a Z33 is returned when a record "cannot be disclosed due to consent or sharing restrictions", and that PD1-12 affects responses, but does not tie the Z33 to PD1-12 = 'Y' or say whether a deceased patient is returned.
    Partly coveredAction: Narrative
    TAB A patient who is not protected (PD1-12 not 'Y') SHALL be returned; a protected patient is returned as a Z33. A deceased patient MAY be returned.
    Recommendation State in 3.5.2.4 that a patient with PD1-12 'Y' is returned as a Z33, and that a deceased patient MAY be returned.

    See the TAB comparison

    qf-tab-rr-01

A Z33 response indicates that the IIS cannot return a patient-level immunization record for the query as submitted. This may occur when no matching records are found, when potential matches exist but IIS policy prohibits returning them, or when a matching patient record exists but cannot be disclosed due to consent or sharing restrictions.

In all cases, Z33 communicates that the IIS has processed the query but cannot provide patient-level immunization information. No follow-up query can resolve the request unless additional or different identifying information becomes available.
