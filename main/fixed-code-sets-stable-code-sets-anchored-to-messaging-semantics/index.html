4.3.2 Fixed Code Sets (Stable Code Sets Anchored to Messaging Semantics)

Quality review 1 warning · 1 note

Findings from automated and editorial checks, for the authors and reviewers. Not part of the guide.

  • Warning Statement s1 Statement combines SHALL, SHALL NOT. Each statement should carry one requirement so it can be tested and referenced on its own.qf-multi-verb-statement-4882ccdb
  • Note 2 requirements were written as paragraphs in the draft and are shown here as conformance statements (wording unchanged): s1, s2.qf-statement-from-paragraph-865f4b84

Fixed code sets are those whose values are intentionally stable and tightly coupled to message structure or processing semantics. These codes do not evolve in response to external clinical developments and are not expected to change outside of a formal guide revision. Their stability allows consistent interpretation across jurisdictions and long-lived implementations.

Fixed code sets are commonly used for message control, workflow intent, or processing instructions rather than clinical description. Because these values often drive logic rather than describe data, unrecognized values can fundamentally alter message handling behavior.

Examples include structural action or control codes such as RXA-21 (Action Code) and message type identifiers (e.g., MSH-9).

Conformance statements

  1. SHALLSystems (including submitting systems and IIS) SHALL use only the values explicitly defined for fixed code sets and SHALL NOT introduce local extensions.⚑s1
  2. SHALL NOTSystems SHALL NOT assume that future values may appear in fixed code sets unless explicitly updated through a new guide release.s2
