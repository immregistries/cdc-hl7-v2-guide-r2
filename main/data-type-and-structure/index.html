4.5.2.5 Data Type and Structure

Quality review 1 issue · 1 note

Findings from automated and editorial checks, for the authors and reviewers. Not part of the guide.

  • Issue Newborn ('NB') names are not held to the family-and-given rule, and other names are over-constrained when an 'L' name is present. The profiles implement the two XPN flavors by slicing the whole PID segment on PID-5.7, not by name repetition. If any repetition is 'L', every repetition (nickname, maiden, and so on) must use XPN_IZ01 and have both family and given name. If no repetition is 'L', every repetition uses XPN_IZ02, where only one of family or given is needed, so an 'NB' placeholder name with one part passes. The two slice conditions also overlap: a patient with an 'L' and an 'N' name matches both. Slicing exists only in Z22; the response profiles (Z31, Z32) always use PID_IZ01 and Z42 uses PID_IZ02.
    ConflictAction: IGAMTAnswers Word comment 36
    Narrative "Official registry and newborn names must contain both a family and given name, while other types (e.g., nickname, maiden) may have only one component." Word comment 36 asks to confirm three statements: (1) XPN.1 and XPN.2 populated for 'L' and 'NB' names; (2) XPN.7 populated for all repetitions; (3) cardinalities and flavors as defined in the data type section.
    IGAMT export
    • Slicing (Z22, PID): PID_IZ01 if at least one PID-5.7 = 'L'; PID_IZ03 if at least one PID-5.7 is not 'L'.
    • PID_IZ01.PID-5 uses XPN_IZ01: XPN.1 R, XPN.2 R, XPN.7 R.
    • PID_IZ03.PID-5 uses XPN_IZ02: XPN.1 C(R/RE) if XPN.2 not valued, XPN.2 RE, XPN.7 R.
    • Z31/Z32 PID_IZ01 (XPN_IZ01) and Z42 PID_IZ02 are not sliced.
    Recommendation Statement (2) exists: XPN.7 is R in every PID-5 flavor. Statement (1) holds for 'L' only. Ask IGAMT whether a slice or co-constraint can apply per repetition (by XPN.7). If not, use a conformance statement such as "each PID-5 repetition with XPN.7 in ('L','NB') SHALL value XPN.1 and XPN.2". Make the two slice conditions mutually exclusive. Decide whether responses should follow the same rule. Statement (3) has no counterpart in the narrative yet; the card should state it once the data type pages exist.

  • Note Narrative uses "must", which reads as a requirement. If it is one, state it as a conformance statement; otherwise consider softer wording.
    Different name types carry different completeness expectations. Official registry and newborn names must contain both a family and given name, while other types (e.g., nickname, maiden) may have only one component.

Different name types carry different completeness expectations. Official registry and newborn names must contain both a family and given name, while other types (e.g., nickname, maiden) may have only one component.

Two flavors of the XPN data type will be defined for this guide-one for the Official Registry Name and one for all other name types-to reflect these differing expectations.
