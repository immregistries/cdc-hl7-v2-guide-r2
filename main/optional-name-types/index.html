4.5.2.4 Optional Name Types

Quality review 1 warning · 1 note

Findings from automated and editorial checks, for the authors. Not part of the guide.

  • Warning Statement s3 TAB Patient Name (PID-5) Updates to Support Patient Matching (Name type code (HL70200) Value Set usage for PID-5 (Table 1)): Conflict. The guide says "Systems SHOULD NOT send names with ambiguous or administrative meaning such as Business, Partner/Spouse, or Licensing names", a SHOULD NOT where the TAB says SHALL NOT, and it does not mention Father's name or the SHOULD NOT codes.
    ConflictAction: Narrative
    TAB 'NAV' (temporarily unavailable), 'TEMP', 'BAD', and 'D' (customary) SHOULD NOT be supported. 'F' (Father's name), 'I' (Licensing), 'K' (Business), and 'P' (Partner/Spouse) SHALL NOT be supported.
    Recommendation Replace s3 with the TAB's two lists: SHOULD NOT NAV, TEMP, BAD, D; SHALL NOT F, I, K, P. Better, add Table 1 to 4.5.2.1.

    See the TAB comparison

    qf-tab-pn-04
  • Note 4 requirements were written as paragraphs in the draft and are shown here as conformance statements (wording unchanged): s1, s2, s3, s4.qf-statement-from-paragraph-bffe033b

Additional HL7 v2 name types (e.g., Assigned, Birth, Adopted, Indigenous/Tribal, Religious) may provide useful contextual detail for certain populations. IIS may choose to accept and store them, though they are not required.

Conformance statements

  1. MAYSystems MAY support optional name types when used for legitimate patient identification.s1
  2. MAYIIS MAY accept these additional name types for local matching needs.s2
  3. SHOULD NOTSystems SHOULD NOT send names with ambiguous or administrative meaning such as Business, Partner/Spouse, or Licensing names.⚑s3
  4. SHALL NOTIIS SHALL NOT process unsupported name types if received.s4
