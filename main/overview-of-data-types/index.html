4.1.1 Overview of Data Types

HL7 v2 messages are composed of segments, and segments are made up of fields. Fields are the core building blocks used in HL7 v2 messaging to transmit information. Data within these fields can be structured into components and subcomponents. The organization and formatting rules for these fields are governed by Data Types, which serve as a mechanism to define the format and constraints of the data to ensure consistency and interoperability across systems.

For example, certain fields, such as address or phone number fields, follow specific formatting rules, regardless of whether they represent a patient's or a next-of-kin's information. These rules are defined through data types, ensuring that common patterns are repeated in a structured and standardized way. Therefore, when reviewing the definition of a field, it is essential to understand the corresponding data type definition, as the type ensures the correct format and interpretation of the data within the field.

ln HL7 v2, each data type is given a unique alphanumeric descriptor, which is defined by the HL7 v2 base standard. However, these definitions are often further constrained in this implementation guide. The local constraints are referred to as 'flavors' of the data types, which can modify field requirements and define which coded values should be used for specific data types.

Thus, when reviewing a field, it is important to understand both the general data type and the specific data type flavor being applied. The data type establishes the base structure, while the data type flavor outlines additional requirements regarding completeness and code set usage.
