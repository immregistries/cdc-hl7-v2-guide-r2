3.5.2 RSP Response Profiles

Quality review 1 warning · 2 notes

Findings from automated and editorial checks, for the authors. Not part of the guide.

  • Warning SISC guidance Guidance for HL7 RSP Messages to Support Interoperability (Query Response Guidance (query is successfully processed); Summary): Missing. The guide never explains QAK-2 or how it relates to MSA-1. The only QAK-2 value it names is 'TM', in the Z31 section. The IGAMT profiles bind QAK-2 to HL70208 (OK, NF, TM, AE, AR) but set no rule linking it to the outcome or to MSA-1.
    MissingAction: Narrative
    Guidance QAK-2 reflects the outcome of the search and is independent of MSA-1, which reports the technical processing of the message. In a successful query, QAK-2 may not be 'AR' or 'AE'.
    Recommendation Add a short section, or a table like this guidance's Table 2, on QAK-2: what each value means, which values go with which response profile, and that QAK-2 and MSA-1 are set independently.

  • Note SISC guidance Guidance for HL7 RSP Messages to Support Interoperability (Query Response Guidance (query is successfully processed)): In narrative only. The guide describes the response profiles as the "controlled set of outcomes" of matching, and its Z33 section says that a Z33 means the IIS "has processed the query". It does not say outright that finding no patient, or several, is a successful query rather than an error.
    In narrative only
    Guidance A query that runs to completion is successful, however many patients it finds (none, one, or more than one). The Z31, Z32, Z33, or Z42 profile is used depending on the query profile and the outcome.

    See the SISC guidance comparison

    qf-sisc-rsp-07

An IIS response reflects the outcome of applying internal patient matching processes and policy constraints to a query request. The response returned depends on the identifying information provided, whether a patient record can be confidently identified, the consolidation state of that record, and applicable IIS disclosure policies.

RSP profiles define a controlled set of response patterns that allow querying systems to reliably distinguish between successful retrieval, ambiguous matching, and conditions where a patient record cannot be returned. Each response type communicates not only what information is being returned, but also why that outcome occurred and what, if any, follow-up action is appropriate.
