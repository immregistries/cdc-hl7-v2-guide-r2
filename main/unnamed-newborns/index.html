4.5.2.7 Unnamed Newborns

Quality review 5 notes

Findings from automated and editorial checks, for the authors. Not part of the guide.

  • Note MIROW guide Immunization Information Systems Patient-Level De-duplication Best Practices (4.1.2, 4.3.1, 5.2.1 (5) - Placeholder names for newborns): Guide adds. The guide supplies the national convention. A placeholder name is marked with name type 'NB' and never sent as the legal name. When the real name is known, the submitter sends both names together, along with the child's complete history, so the IIS can link the records.
    Guide adds
    Best practice Nearly all interface data needs pre-screening. IIS may decide not to use records with names like Baby Boy, Baby Girl, BB, or BG, and should remove placeholder words before matching. In the longer term, "placeholder information could be standardized by convention on a national scale".

Many newborns receive vaccinations before their permanent names are entered into hospital or EHR systems. The problem for IIS is not occasional naming delays, but the widespread practice in some hospitals of never updating placeholder names. These placeholders, such as "Baby Girl Smith" or "Infant Jones", remain indefinitely, leaving the IIS unable to match vaccination records once the child's real name appears elsewhere.

This guidance defines how to represent those cases in HL7 v2 messaging. It does not prescribe how hospitals or EHRs choose or format placeholder names internally. The goal is that all systems can clearly indicate when a submitted record represents a newborn with a temporary name, using a standard HL7 v2 mechanism.

Hospitals and submitting organizations should review their workflows to ensure that once a newborn's name is known, that information flows promptly to all connected systems and to the IIS. This ensures that the initial vaccination record, often the first dose of Hepatitis B, is properly linked to the correct child record.

Conformance statements

  1. MAYSystems MAY generate a placeholder given name when the newborn's permanent name is not yet known.s1
  2. SHALLIf a placeholder name is used, systems SHALL mark it with the name type code 'NB' in PID-5.s2
  3. SHALL NOTSystems SHALL NOT use the 'L' name type for placeholder newborn names.s3
  4. SHOULDSystems SHOULD follow established newborn naming conventions (e.g., those recommended by the Joint Commission or AHIMA) to improve operational consistency when converting internal records for submission.s4
  5. SHALLSystems SHALL update the record as soon as the permanent name is known and SHALL resubmit with both the permanent name ('L') and the placeholder name ('NB') in the same PID-5 field.⚑s5
  6. MAYSystems MAY continue sending both names temporarily to assist reconciliation.s6
