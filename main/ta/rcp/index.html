What was asked

RCP questions all concern RCP-2 (Quantity Limited Request): how many candidate patients a querying system should request, how an IIS should combine RCP-2 with its own maximum, and how the limit interacts with Z31, Z32 and Z33 responses and the too-many (TM) status. RCP-2 Quantity Limited Request

When returning a Z31 list of candidates for a multiple-match query, is there a limit on how many patients (PIDs) should be returned?

Asked 1× · 2021 · QBP/RSP · Answered · Fields: RCP-2 · Related: Query & Response Behavior, PID

Answer given

The limit is two-fold: the querying system can (should) specify the maximum number of matches it wants in RCP-2, and the IIS can set its own maximum for policy reasons (not explicitly messaged). Return no more than the smaller of the two; if more matches exist, respond with "too many" candidates. E.g., IIS max 3 and requester asks 5: return up to 3; IIS max 3 and requester asks 2: return up to 2.

What is a reasonable value for an EHR to send in RCP-2 as the maximum number of Z31 candidates, and is there IIS data to help choose it?

Asked 1× · 2022 · QBP/RSP · Partly answered · Fields: RCP-2 · Related: Query & Response Behavior, Patient Matching & Deduplication

Answer given

There is no consensus-based national recommendation, and the AIRA Functional Guidance for Query-Response does not specify a number. RCP-2 is set by the querying system to indicate the maximum number of potential matches the IIS should return; the IIS may also have its own internal limit, and the lower of the two should apply. Values of 10 and 30 have been seen in practice but are probably too high for busy clinic staff; several reviewers felt 10 is likely too many and 5 seems reasonable. One clinical perspective: if candidates are returned with equal likelihood, limit to a smaller number (around 5); if likelihood scores are returned, the cutoff could instead be based on match likelihood (e.g., 90% or greater). The right number depends heavily on how well each IIS matches records, both in consolidating histories and in responding to queries, which varies by IIS, so a universal recommendation is difficult. The question was taken to the May 2022 HL7 Immunization User Group for a poll of IIS on their maximum multiple-match return count and to a later community panel on query functionality.

How should an IIS handle too-many (TM) results depending on RCP-2? (An IIS returned a Z32 with QAK-2 = TM when RCP-2 = 1, a Z31 with candidates but QAK-2 = TM when RCP-2 = 2, and a Z31 with three candidates when RCP-2 = 5.)

Asked 1× · 2022 · QBP/RSP · Answered · Fields: RCP-2 · Related: QAK-2, MSH-21

Answer given

The IIS Functional Guide Vol. 1 (Query and Response), section 7.5, says the IIS should honor the lower of its own maximum-returned policy and the quantity requested in RCP-2. When a too-many condition is reached the IIS should not list possible matches; the CDC IG (Chapter 6, response to different outcomes table) indicates returning a Z33 with QAK-2 = TM.

Applied to the examples: (1) RCP-2 = 1 returned a Z32 profile with TM status, which is inconsistent; Z32 means a single patient was found and returned, so it should be either a Z33 with TM or a Z32 with a full record. (2) RCP-2 = 2 returned a list of candidates (Z31) while also indicating TM; if there were only two matches within the threshold the list is correct, but the TM status is inconsistent. (3) RCP-2 = 5 was consistent but had several message-structure problems, mostly missing data. Use the NIST IZ Tool to check the format of response messages.

Per the IG as written, a Z44 cannot return a Z31 profile. However, NIST later clarified that "X" was not an appropriate way to define that constraint and issued a clarification (contents not captured in the record).
