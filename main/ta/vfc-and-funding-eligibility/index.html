Funding Source vs Eligibility: Concepts and Codes

How should vaccine funding source and vaccine funding program eligibility be messaged, and how are the two concepts related? Why are some IIS requests for these values hard for providers to implement?

Asked 2× · 2020–2021 · VXU · Answered · Related: OBX-5, RXA-9, RXA-15

Answer given

EHR systems should be able to message both concepts. Each IIS decides which one (if not both) it wants to read and use in its vaccine program. (The 2021 request about why IIS requests are hard for providers to implement had no answer recorded.)

Is there a standard practice for consuming, storing and using funding source and eligibility from HL7? For example, one IIS ignores funding source, bases inventory deduction only on the financial class (VFC eligibility) code and provider type, and rejects some CDC eligibility codes (e.g., wrong for age or clinic type). How do jurisdictions distinguish the Public, Public VFC and Public non-VFC funding codes?

Asked 1× · 2023 · VXU · Answered · Related: OBX-5, OBX-3, RXA-9

Answer given

Much of how funding source and eligibility are captured is set by each jurisdiction's policy. Helpful resources: - "IIS and EHR Common Areas of Variability Based on Jurisdictional Law/Policy": explains national-level reasons for variability and describes different funding source models (from p. 3), which help decide which codes map to which funding categories. It links to the MIROW guides "Decrementing Inventory Via Electronic Data Exchange" and "IIS Collaboration with VFC and Grantee Immunization Programs". - IIS Functional Guide, Volume 2: eligibility and funding source recommendations start on p. 66. - "Recording Dose Level Eligibility in Immunization Information Systems (IIS)": the national view of challenges and opportunities in capturing dose-level eligibility.

Whether to use a single Public funding source or to split Public VFC and Public non-VFC is a jurisdictional choice. The main recommendation is that what is sent over HL7 should record what actually happened, so that the IIS captures complete data. Do not reject at the interface. Instead, find and fix illogical eligibility/funding combinations afterward through data quality checks such as provider report cards. AIRA's Data At Rest assessment also measures how often these illogical combinations occur among 0-2 year olds.

COVID-19 Funding and Eligibility

Which funding source and eligibility codes should providers send for COVID-19 vaccine doses so that the IIS will decrement inventory correctly, given that private and VFC are not appropriate? Is there a standard HL7 code?

Asked 3× · 2020 · VXU · Answered · Related: OBX-5

Answer given

At the October 2020 SISC call, most participants agreed that the proposed solution is workable: code the funding source as Public (VXC50) and eligibility as Not VFC Eligible (V01). This applies during the first phase, while the vaccines are federally funded and freely available. Once they are no longer federally funded, COVID vaccines should be coded as appropriate.

SISC discussed various options (creating new codes, various combinations) and settled on this recommended combination, recognizing that no combination was perfect, and followed up with a poll. It is a best practice or recommendation rather than a hard rule, for several reasons: - Some providers may not be trained to select these values correctly. - All COVID vaccine is federally funded. - Provider systems, end users and IIS inventory decrementing rules are complex.

VAMS, being COVID-specific, hard-codes these values in its HL7 instead of asking end users to populate them.

Are the recommended COVID funding type and eligibility codes important only for HL7 messaging, for systems using the IZ Gateway, and for IIS internal processing? Would this information need to go back to CDC?

Asked 1× · 2020 · VXU · Answered · Related: OBX-5

Answer given

Yes, they are important for HL7 messaging and for systems using the IZ Gateway, most specifically VAMS, a short-term COVID-specific application, to meet HL7 requirements. The biggest concern was how each IIS uses the codes for internal processing. At that time the information was not in the CDC data lake (CVRS) file, and there had been no discussion of reporting it to CDC.

Per the core data elements list, are funding eligibility and funding source required for patients older than 19?

Asked 1× · 2019 · VXU · Answered · Related: OBX-5, RXA-9

Answer given

The core data elements documentation does not specify that they must be sent for all patients of all ages. Links to the updated CDC list and the new Functional Guide were provided. Programs sometimes add their own requirements (e.g., the state VFC program may need it). Requiring it may also require EHR screen changes if the VFC questions are currently age-based.
