What was asked

This section gathers questions about how IIS validate, accept, reject or clean incoming data, and about related format issues. Format issues include timestamp syntax, time zones and non-ASCII characters. Validation issues include inconsistent vaccine codes (CVX/MVX/NDC/lot) and product-specific documentation such as nirsevimab. Recurring themes: - Distinguishing "impossible" errors (reject or flag) from "possible" errors (accept and review). - Many acceptance and cleaning decisions are IIS business rules that should be documented in local guides. - Timestamp formatting edge cases (fractional seconds, offsets) cause avoidable rejections.

Character Encoding

A provider's system fails to parse a QBP response because the response contains a non-ASCII character (a UTF-8 en dash, hex E2 80 93) in a provider name, and MSH-18 does not declare a character set. Is there guidance on handling non-ASCII characters in outbound messages? Should the IIS strip or replace them?

Asked 1× · 2021 · RSP · Answered · Related: MSH-18 (see also section 29, special characters / Latin-1 guidance)

Answer given

The IZ guide specifies that string values must use ASCII characters 32 through 126. Before sending, characters outside this range should be replaced with the ASCII character that best represents them, replaced with some other value, or removed. If the occurrence is rare and the data is not critical, the IIS may choose to handle it as a one-off data quality fix.

Is there a document IIS follow for nirsevimab documentation? Will an IIS reject a nirsevimab immunization if it is documented incorrectly?

Asked 1× · 2024 · VXU/ACK · Answered · Related: RXA-5, ERR-4

Answer given

IIS process reported nirsevimab administrations the same way as other reported immunizations. If nirsevimab is reported as administered, the IIS expects the fields associated with an administered dose to be accurately populated in the VXU. As with any VXU, the IIS will return errors in the ACK if it encounters issues, such as expected fields not populated or invalid data. Treat nirsevimab like any other immunization for data capture and reporting.

Can a site document a single nirsevimab (Beyfortus) administration of 200 mg with injection site "both thighs IM" when it was actually given as two separate doses, or will the IIS reject it?

Asked 1× · 2024 · VXU · Answered · Related: RXA-6, RXR-2

Answer given

IIS strive for records that accurately reflect the vaccination event that actually occurred (AIRA Data Quality Assurance in IIS guide). That guide divides data quality issues into two kinds: - Impossible errors physically could not have occurred. They should not enter the IIS, or they should be flagged and rectified. - Possible errors could have clinically occurred. They should not be rejected, but should be flagged for review or surfaced by trend reports.

Given the available product formulations, a report of a single 200 mg nirsevimab administration is closer to an impossible error. At a minimum, IIS would likely flag it for follow-up, to understand what was administered and make the record reflect reality. Report the two injections as they were given.

Acceptance and Rejection Rules

Is there a list of the core data elements whose absence makes an IIS reject an HL7 VXU (and of those that produce AE warnings while still loading)? Or must each element be tested individually and the ACK recorded?

Asked 1× · 2024 · VXU/ACK · Partly answered · Related: Acknowledgement & Error Handling, Local Profiles & Jurisdictional Constraints

Answer given

AIRA did not point to an existing list. As a starting point, it shared a minimal VXU that the IIS had accepted during prior testing. That message contained: - MSH with sending/receiving facility. - PID with only an ID, legal name, birth date and sex. - A basic ORC. - RXA with administration date, CVX, amount and units, administered information source, lot number and manufacturer. - OBX segments for VFC eligibility and VIS document type/date presented.

AIRA suggested trimming elements from this message, starting with the VIS information, to find what the IIS still accepts.
