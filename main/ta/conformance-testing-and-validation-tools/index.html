Conformance Testing & Validation Tools

Working analysis for the authors, from questions asked of AIRA's technical assistance service. Not part of the guide.

34 questions. Findings: none
Not yet assessed

What was asked

This section covers questions about the tools and programs used to verify HL7 v2 immunization interfaces: the NIST Immunization (IZ) validation tool, AIRA's AART assessment and validation program (Submission/Acknowledgement, Query/Response, Data Quality Incoming/Ongoing, CDS, and transport), test environments and sample/synthetic test data. Many questions ask how to read AART reports, why a measure was met or not, and what an IIS must change to reach Basic or Complete validation. Recurring themes include Query Measure 5 (multiple-match), which AART could not reliably test and does not score, the use of a follow-up query to confirm what an IIS stored, and the role and limits of NIST warnings.

IG clarifications suggested when the TA records were consolidated (5)
  • Clarify when an invalid or incomplete query should yield an RSP Z33 versus an ACK Z23.
  • RSP evaluation status supports only Valid/Not Valid; address the CDSi "Extraneous" status and consider a way to pass an assessment date in queries.
  • Document the meaning and intended use of NIST validator warnings for implementers.
  • Consider documenting expected response-time performance (currently only in AART measures and the general "timely" language of IIS Functional Standards).
  • Clarify requirements for namespace prefixes in CDC WSDL SOAP fault responses.

An IIS wants all new submitters to produce messages with no NIST errors and no NIST warnings. Is that a proper use of the NIST tool, given properly formatted messages can generate warnings?

Asked 1× · 2019 · general · Answered

Answer given

No. NIST warnings indicate which parts of the message need additional testing to verify they are working properly; they do not indicate problems with the message per se. As the warning text indicates, there could be a problem, but further investigation would be needed. Requiring zero warnings is not an appropriate use. There needs to be documentation and education for the community about the meaning and use of NIST warnings.

When AART sends test cases to an IIS, how many messages does it send, how are they generated, and are they expected to be kept as new test patients? Are there sources of generated sample VXUs for loading test data?

Asked 1× · 2023 · VXU/QBP · Answered · Related: Onboarding & Interface Testing

Answer given

AART test cases come in many forms, and each tests something specific. Some messages are deliberately bad to test rejections. Others are valid messages repeated in bulk, for example a couple thousand each with a different CVX or NDC code. After each test message AART queries the data back, even for "bad" messages, to understand ACK behavior and reject versus accept versus storage. Every test run uses new, unique patient demographics, which are not expected to merge except in the Patient Matching content area. AART has no use for them after the query, so the IIS can keep, discard or reuse them. Across HL7 and CDS tests (Testing & Discovery and Assessment), expect roughly 2-3 thousand VXUs and QBPs per run. AART is not designed for load testing, though multiple runs can supply seed data. Larger generated sets of sample VXUs (100 up to 1 million messages), built for FHIR Bulk Query testing, are available at https://florence.immregistries.org/#generatedData.

If query (QBP) access for AART testing had to be opened to an IIS test environment that contains actual patient data, what protections does AART have, and what would AIRA recommend?

Asked 1× · 2025 · QBP/RSP · Answered · Related: Query & Response Behavior

Answer given

AIRA described technical, process, and legal protections.

Technical/testing: all AIRA-generated test data appends "AIRA" to patient first and last names (e.g., ThomasAIRA), with limited exceptions in some patient-matching scenarios that remove it to avoid false positives/negatives, and in Query Measure 5 (multiple-match RSP) when the IIS supplies one of its own known test patients. AART only queries for records AIRA itself created, except Query Measure 4 (querying for a patient that was never submitted, to test Patient Not Found, still using an AIRA-suffixed name) and Query Measure 5 when using an IIS-supplied test patient. AIRA confirms that RSP data returned by the IIS matches the patient data submitted in the VXU; when it does not match, the returned data is redacted before storage in AART, so AIRA staff cannot access such records in identified form. AART is hosted in AIRA's FedRAMP-certified Azure cloud environment.

Process/data: messages older than 2 years are moved out of AART to cold storage and deleted after 7 years, and staff who extract AART data for analysis use a secured virtual desktop environment.

Legal/insurance: AIRA carries cybersecurity insurance with $3 million aggregate coverage, and its privacy and terms-of-use documents are published at https://www.immregistries.org/organizational-documents.

AART Program, Validation Levels & Reading Reports

Must a new IIS component's HL7 interface, IZ Gateway connection, and inventory management be validated by AIRA or another third party (including CDC) before go-live?

Asked 1× · 2022 · general · Answered · Related: Onboarding & Interface Testing

Answer given

AIRA's Measurement and Improvement program is voluntary, but CDC has been asking grantees whether their systems have been independently verified. The AIRA project is currently the only known independent method of verifying that an IIS follows HL7 standards, and nearly all IIS have signed up to be measured in at least one area. In addition, AIRA has a software product recognition program that software vendors can join to receive independent verification that their software is capable of meeting IIS standards. This does not count as validation for the IIS itself, but gives the IIS confidence that if it implements the software it will be able to achieve validation. The program is free but requires the vendor to expose an HL7 interface that AIRA can test independently.

In AART, is message validation based on content or structure alone, and does AART assess details beyond what is visible in the test case details (e.g., consistency checks)?

Asked 2× · 2022 · QBP/RSP · Answered · Related: Query & Response Behavior

Answer given

It depends on the test. AART tests are designed so each measure tests the narrowest thing possible, so that a failure happens for the reason being tested rather than some unrelated common issue; this makes pass/fail results more informative. For example, the first query test only requires that an RSP with the correct profile type is returned, without verifying the message structure, whereas Measure 3 expects the RSP for both response types to be correctly formatted. Passing Measures 1 and 2 but failing 3 shows an IIS has implemented something close but still has work to do. Measures then feed validation, where some are required for Basic Validation and the rest for Complete Validation, distinguishing IIS that meet critical parts of the standard from those that meet all of it. Details for each test are available by stepping through each measure in the AIRA Sandbox results or the published test descriptions; sometimes tests use NIST results, other times they check specific aspects of the returned message.

For query testing specifically, AART mostly looks at whether the RSP is formatted correctly and contains the type of data expected, e.g., whether a match was returned for a query for a known patient, or whether a deliberately bad query resulted in an error response.

When reading AART test case details, which messages show exactly what was sent to the IIS and what it returned, and which are evaluated? What is the "Start Message"?

Asked 2× · 2023 · VXU/ACK/QBP/RSP · Answered · Related: Acknowledgement & Error Handling, MSA, Query & Response Behavior

Answer given

It depends on the content area. As a rule, look at the two messages just before the Testing Log. For Submission that is the VXU and its ACK. For Query and Response it is the query and response that follow the VXU and ACK, again the two messages before the Testing Log. Data Quality Incoming/Ongoing has both submission and query test cases, so again look at the two messages above the Testing Log. The Testing Log shows the logic AART used to evaluate the measured test case. The "Start Message" is the base template AART uses to generate the test case.

Example: test case 13.1 ("ACK conformance validation on message with data quality issue") shows an Update (update message submitted, NOT accepted by IIS) and a Query (query, and Z33 with QAK-2=NF returned). Because 13.1 belongs to the Submission assessment, it evaluates only the "Update Message Submitted" (the VXU AART sent) and the "NOT Accepted by IIS" message (the ACK the IIS returned); those two determine the Measure 13 result. The Query/Response pair is not evaluated for 13.1 and can be ignored.

In AART Submission/Acknowledgement Measure 10, an IIS was scored "deviates" on all five test cases because it does not accept messages without a patient address. Why is a deviation acceptable here when not meeting other measures results in failure?

Asked 1× · 2026 · VXU/ACK · Answered · Related: PID-11

Answer given

Measure 10 tests whether the IIS accepts messages containing only the minimally required information from the HL7 2.5.1 IG (the R fields); it is not a conformance check. The test case expectation is that the IIS accepts the message. AIRA's outcome definitions: - "Deviates": the IIS can meet the expectation with modification to the test case or expectation that supports a local business need, policy, or law. - "Does not meet": the IIS cannot meet the expectation due to non-standard requirements, capability limitations, or otherwise arbitrary requirements that do not support local business need, policy, or law.

Requiring address is driven by local policy, is a common IIS requirement, and is HL7 "legal" because PID-11 is RE. Something would be flagged "does not meet" if the IIS were doing something not HL7 legal. Measures & Tests documents for each content area are on the AIRA site (https://www.immregistries.org/m-i-measurable-areas), including the Submission/Acknowledgement measures document.

Submission/Acknowledgement & Data Quality (DQI) Assessment

How are AART Data Quality Incoming/Ongoing (DQI) test cases evaluated, and how can a measure be met when one of its sub-tests shows FAIL or appears skipped?

Asked 2× · 2022–2024 · VXU/ACK/QBP/RSP · Answered · Related: Data Quality & Validation, ERR

Answer given

For DQI testing AIRA submits a VXU reflecting the data quality condition described in the test case and then sends a QBP for the patient. Both the ACK and the RSP are used to decide whether the IIS met the expectation. The IIS meets the test case if either (a) the HL7 ACK identifies the data quality error, or (b) the HL7 RSP does not include the erroneous data. A measure is not met only when neither the VXU acknowledgement nor the query response meets the expectation. The methodology is described in the "Measures and Tests for Assessment - Data Quality Incoming/Ongoing" document (pages 4-5).

Examples: (2022) An IIS passed Measure 5 even though test 5.1.1 did not detect the data quality error (details visible under Test Details); for test 5.1.2 the RSP came back without the state populated, which counts as success, so Measure 5 was met. (2024) Sub-test 6.1.1 (patient address country) showed FAIL with no check or X because the ACK did not flag the problem, but the query response (6.1.2) met the expectation, so the overall measure was met and 6.1.1 is shown without a check or X.

AIRA cannot prescribe exactly when specific ERR segments must be returned: some are broadly agreed by the IIS community (e.g., missing DOB), but for others (often RE fields) an IIS may or may not choose to raise an ERR segment. (The 2022 IIS returned ERR warnings only for patient ID, first/last name and DOB, not for phone, address, race or ethnicity.)

The IG says PID-7, PID-8 (Unknown allowed) and RXA-3 are required in Z32 responses, yet AART test cases send VXUs with missing or invalid values for these fields, query for them, and expect the field to be empty (or Unknown) in the RSP. Why do test cases conflict with the IG, and should more such conflicts be expected?

Asked 1× · 2024 · VXU/QBP/RSP · Answered · Related: PID-7, PID-8, RXA-3, Query & Response Behavior

Answer given

This is intentional and should be thought of as negative testing. Each AART test case declares whether the IIS should accept the message, accept it with an error or warning, or reject it. Because EHRs and providers do send non-standard messages, the tests copy that and expect the IIS to react to poor data quality (missing, invalid, or conflicting values): either reject (ERR-4 = E) or accept with a warning (ERR-4 = W).

AIRA queries for that data afterward because it has no access to the IIS user interface. The query is the only way to check that what the ACK reported matches what the IIS actually stored. A good outcome is an RSP consistent with the ACK, for example showing that rejected data was not stored.

Query/Response Assessment

What does an IIS need to do to reach Basic and then Complete AART validation for Query and Response, and what do failures on Measures 3, 5 and 6 mean?

Asked 2× · 2022–2023 · QBP/RSP/ACK · Related: Acknowledgement & Error Handling

Answer given

  • Measure 3: the IIS must include a forecast in the response to pass. For one IIS (2023), Measure 3 was the only measure missing for Basic validation, and it passes once the IIS supports returning a forecast.
  • Measure 5 (multiple match): an AIRA-side issue; AIRA has difficulty creating the multiple-match scenario and in future will ask IIS to supply a patient name that yields a multiple-match response. It is not currently part of Basic or Complete validation but may be later.
  • Measure 6: the test sends a query designed to produce a Z33 (error/no-data response profile), but the IIS returned a Z23 ACK. A Z23 is sensible and acceptable for this rare scenario, but it prevents AIRA from verifying the Z33 format; the IIS should return a Z33 in this situation to receive Complete validation. For the 2023 IIS, passing Measure 6 was the only remaining step to Complete.

Once the response includes CDS forecast results and the error-situation response is changed to Z33, the IIS should qualify for Complete Query Validation. (Further details for the 2023 case were in the original correspondence but are cut off in the record.)

Can AIRA share the specific subset of CDSi/FITS test cases used in the AART quarterly CDS assessments (Measures 1-12)?

When building CDS test cases sent as HL7 messages, how does FITS handle intervals in months and years, and how are they turned into dates in the test messages (e.g., is a month a fixed number of days)?

Asked 1× · 2024 · VXU/QBP · Answered · Related: RXA-3, PID-7

Answer given

FITS follows the CDSi date calculation rules: a year is 12 months, and a month is calendar-based, not a number of days. For example, adding 18 months adds 18 to the current month, then adjusts the year, then adjusts the day of the month if it overflows. FITS test cases define intervals (e.g., 1 month vs 30 days); when a test is run these intervals are resolved against the current test date to derive exact dates, and the resulting HL7 messages contain those exact dates (e.g., PID-7, RXA-3). Running the test on another day produces different dates. The original message is stored, and what is stored per test is the expected recommended and earliest dates rather than the vaccination dates. A system storing tests as HL7 messages with shifted dates cannot recover whether an offset was "1 month" or "30 days"; the interval definition must be kept with the test case.
