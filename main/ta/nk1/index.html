NK1 Next of Kin / Associated Parties

Working analysis for the authors, from questions asked of AIRA's technical assistance service. Not part of the guide.

11 questions. Findings: none
Not yet assessed

What was asked

Questions about NK1 cover who belongs in the segment (responsible party, guardian, emergency contact, foster parent), relationship coding in NK1-3 (Table 0063), address and phone component handling (NK1-4, NK1-5), and whether NK1 may or should be returned in query responses. Recurring themes are the IG's loose "suggested values" for relationships, the lack of a way to flag a legal guardian, and IIS validation that is stricter than the standard (e.g., warnings on deprecated XTN components).

IG clarifications suggested when the TA records were consolidated (4)
  • Define how to indicate that an NK1 person is the patient's legal guardian (future guidance planned).
  • Remove meaning assigned to the first occurrence of repeating fields (e.g., "primary"/mailing address first) and rely on type codes.
  • Allow NK1 in the Z42 response profile (now in AIRA TAB).
  • Clarify the NK1-35 race coding system (CDCREC vs HL70005) to match PID-10.

Asked 1× · 2026 · RSP · Answered · Related: NTE; Immunization Evidence (refusals, immunity, contraindications)

Answer given

NK1-3 Relationship

Is there a relationship code for a foster parent in NK1? Providers cannot find an appropriate option for a child in foster care (a ward of the state).

Asked 1× · 2024 · VXU · Answered · Fields: NK1-3 · Related: NK1

Answer given

A foster parent is usually not considered a guardian but a caregiver, so code the relationship in NK1-3 as CGV (Caregiver).

Also, the current IG supports sending Next-of-Kin (usually the mother or father) but does not require that the NK1 is the guardian or that the submitter say whether the person is the guardian. IIS sometimes assume the mother is the guardian for patients under 18, but that is not always true (some mothers lack parental rights, and some care for disabled adult children). If an IIS needs to determine the actual guardian, AIRA can provide further guidance. This area is planned for more formal guidance.

An EHR is sending the value "27" in NK1-3 instead of a valid code from HL7 Table 0063, causing errors. How should this be resolved?

Asked 1× · 2023 · VXU · Answered · Fields: NK1-3 · Related: Code Sets & Vocabulary

Answer given

NK1-3 is the next-of-kin relationship. The site appears to be sending its internal relationship codes rather than the standard HL7 values (from Table 0063, such as MTH, FTH, GRD). AIRA had not heard of this specific issue with this vendor. The resolution is to tell the site that it needs to configure its system to send the correct standard relationship codes. How to do this varies by vendor and the site may need to contact its vendor, but because the vendor had to demonstrate this capability to certify its system, the local site should be able to make the change using the software it already has.

Is there an expected set of NK1-3 relationship values an IIS must accept and store, or must it accept all CDC values (e.g., PHIN VADS relationship value set 2.16.840.1.114222.4.11.3365)?

Asked 1× · 2024 · VXU/RSP · Answered · Fields: NK1-3 · Related: Code Sets & Vocabulary

Answer given

In the current IG the relationship values are "suggested values", and there is no requirement that any specific values on the list be accepted or stored. The PHIN VADS value set contains the same values as the guide. An IIS may choose to accept any or all of them, but AIRA encourages accepting all the values defined in the guide since that gives the most information about the patient. AIRA is updating guidance for these values and welcomes feedback on values IIS see and do not want to accept.

NK1-4 Address

How is the "primary" address defined for NK1 (and other repeating address fields)? Does the first occurrence equate to the mailing address?

Asked 1× · 2016 · VXU · Answered · Fields: NK1-4 · Related: PID-11; Version & IG Interpretation

Answer given

"Primary" is not well defined. A SISC survey of IIS found inconsistent definitions; in some cases primary equates to mailing, but that is not guaranteed. The survey is partly to see whether the next IG version can remove text assigning meaning to a particular occurrence of a repeating field, which would require systems to use the type code that is part of the address, telecommunication number, name, etc. For now, a sending system should determine what it considers its "primary" address, and a receiving system should not assume anything about the first occurrence other than that it is what the sender considers primary. Sending and receiving systems should discuss and agree on what data is sent and where during integration.

What address type should be used in NK1-4 (address type component) when returning NK1 in an RSP: P, L, M or H? State IGs vary.

Asked 1× · 2024 · RSP/VXU · Answered · Fields: NK1-4 · Related: PID-11; Conformance Testing & Validation Tools

Answer given

Ideally the system knows what type the address actually is and codes it accordingly, but few systems capture this and end users may not document it correctly, so a default value is often used. Conformance testing will not fail any legal value from the table, since it cannot know whether the value is correct (there is no context-based test comparing what was sent with what was returned). If the type is unknown, "P" is as good as any other value. The current standard says the mailing address must be sent first, but the next guide is expected to remove that requirement. When sending, code the address type as best you know; when receiving, accept what is sent.

NK1-5 Phone Number

An IIS warns that it does not recognize a phone number unless NK1-5.1 (the deprecated telephone number component) is populated, even though area code and local number components are sent. Should it issue this warning?

Asked 1× · 2021 · VXU/ACK · Answered · Fields: NK1-5 · Related: PID-13, ERR-4

Answer given

XTN component 1 is deprecated by the standard, so its absence should not cause an error. AIRA would not issue a warning for this; it is likely a configurable item in the IIS that can be turned off.
