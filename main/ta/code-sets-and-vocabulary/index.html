What was asked

This section covers questions about the vaccine and related code sets used in immunization messaging. These include CVX, CPT-to-CVX mappings, NDCs and their start/end dates, and value sets distributed through the CDC IIS code set pages and PHIN VADS. It also covers vocabulary for demographic data (race/ethnicity, sexual orientation and gender identity, character sets). Recurring themes are: - How to code products that do not fit cleanly: unspecified, non-US, clinical trial, non-vaccine and newly released products. - How to interpret mapping changes and NDC end dates. - Why coded values are required instead of free text. - Where to find authoritative value sets as PHIN VADS is retired.

IG clarifications suggested when the TA records were consolidated (6)
  • Provide a stable, published home (or embedded tables) for value sets currently on PHIN VADS: contraindications, reactions, VIS vaccines/barcodes and special indications. The IG should also name an alternative authoritative source once PHIN VADS is retired.
  • Clarify the vaccine group mapping for ambiguous unspecified codes (e.g., CVX 109), including what vaccine group value an IIS should return in RSP messages, and whether unspecified CVX may appear in forecasts.
  • Define the supported character set for names (likely Latin-1, versus the current ASCII 32-126 string guidance) and how to represent characters outside it. Clarify MSH-18/MSH-19 use.
  • Address how to message sexual orientation and gender identity separately from administrative sex (PID-8), aligned with the HL7 O&O work.
  • Clarify expectations for HL7 table values unlikely to apply to IIS (e.g., Table 0203 ANT, DEA, GL), covering both acceptance and return in RSP.
  • Consider guidance on whether and how non-vaccine products (immune globulins, TB tests) are recorded and messaged.

ACIP publishes recommended abbreviations (short names) for vaccines. Are IIS expected to follow these abbreviations or create their own short names? Does any standard require them?

Asked 1× · 2022 · general · Answered · Related: RXA-5

Answer given

No published standard requires IIS (or EHRs) to adopt specific vaccine short names, such as those shown in drop-downs. CDC distributes the official codes and names for vaccines in the CVX code set. Short names do not matter for interoperability: IIS ignore the text label sent in HL7 messages and process only the code. The ACIP abbreviation list exists so readers can understand ACIP recommendations. It is not a standard for clinical settings or for how EHR systems must be configured, although adopting it might help correlate clinical practice with ACIP. There are no national requirements for IIS short name conventions.

What is the benefit of requiring coded values (e.g., VXC50) instead of human-readable values (e.g., "Public Funds")? The receiving computer only needs a value that matches its database, so why not allow, for example, "Left Deltoid" in RXR, or map several incoming variants to one local value?

Asked 1× · 2023 · VXU/general · Answered · Related: RXR-1, RXR-2, OBX-5

Answer given

A computer does not care whether a code is readable, but there are practical reasons for opaque codes. Codes need to be technically stable, while labels often get debated and changed for years. Keeping human meaning out of codes lets labels change without affecting operations.

Historically, IIS did accept free-form local values when electronic exchange began (and not always in HL7). Each provider used different text for the same concept ("LD", "123" and "LefDel" for left deltoid), and even for vaccines (Pnu, Pneumo, PCV, 48, etc.). This required extensive mapping and maintenance for each trading partner and was not a sustainable model. Standard code sets avoid that ambiguity and streamline onboarding.

The CDC CVX-to-vaccine-group mapping lists CVX 109 (pneumococcal, unspecified) under two vaccine groups (PPSV and PCV), and maps it to specific codes (33, 152) instead of back to itself as most unspecified codes do. Why would one CVX map to two groups, and is that allowed from an HL7 standpoint?

Asked 1× · 2024 · RSP · Answered · Related: OBX-5, RXA-5

Answer given

CVX 109 is mapped to both groups because the code is not specific enough to show whether the dose was a pneumococcal conjugate (PCV) or a pneumococcal polysaccharide (PPSV) vaccine. In effect, the listing represents that code 109 includes both PCV and PPSV. Because of this ambiguity, code 109 is one of the most problematic unspecified codes. For context, the CDSi project lumps PCV and PPSV into a single Pneumococcal vaccine group. Given recent PCV advances, PPSV is expected to see very limited use going forward (PPSV is not recommended at all after PCV20 or PCV21).

New CPT codes distinguish COVID booster/third doses for reimbursement. Could HL7 messages use these codes so that IIS can track third doses and boosters without relying on internal evaluation logic?

Asked 1× · 2021 · VXU · Answered · Related: RXA-5

Answer given

It is not as simple as it appears. The CPT vaccine product code stays the same (e.g., 91300 for Pfizer). Only the administration code differs (e.g., 0001A, 0002A, 0003A), and IIS are not known to collect administration codes, nor EHRs to submit them. The immunocompromised additional dose is the same formulation, so there will be no new NDC or CVX codes. Those code systems describe the formulation of the product, not the intent of administration or the condition of the patient. If booster formulations differ (e.g., a half-dose formulation), new NDC/CVX codes would follow.

NDC Codes

How should NDC start and end dates be managed? What does it mean when a vaccine NDC is retired or has an end date in the CDC NDC crosswalk, and can an IIS safely inactivate NDCs with an end date?

Asked 2× · 2018–2025 · VXU · Answered · Related: RXA-5

Answer given

CDC NDC start and end dates are approximations derived from the marketing start/end dates in FDA drug listings. The end date is when CDC considers the NDC retired in its code sets, and the FDA retired status may lag behind it. Manufacturers use the marketing end date inconsistently. Some mean the product can no longer be ordered, although unexpired stock may remain in provider inventories. Others retire the NDC only once all product has expired.

Dates are more precise in two cases: - Seasonal influenza: the end date is the season end (e.g., 06/30), and vaccine should not be given after it. - COVID-19/EUA vaccines: dates are aligned with EUA authorization.

The Consolidated NDC Crosswalk gives end dates for both unit of sale and unit of use. AIRA's interpretation is that the end date cannot be trusted for classical data quality purposes, such as rejecting doses after it. Depending on the manufacturer, it may represent last order, last expiry, last shipment or marketing end. "Date no longer marketed" is not trustworthy as a last-expiry date, and even with an expiry date a buffer would be prudent. An IIS should therefore not simply inactivate NDCs at their end date if providers could still be administering doses.

Is there any national activity to create an NDC list/crosswalk for non-vaccine CVX codes (e.g., immune globulins) like the one maintained for vaccines?

Asked 1× · 2024 · VXU · Answered · Related: RXA-5

Answer given

There is currently no such list. CDC has discussed adding NDCs and crosswalks for non-vaccine immune products such as immune globulins and has done a feasibility analysis. The barrier is interpretive, not technical. Treating these products like vaccines could imply that they are immunizations or confer immunity, which may be misleading: IGs are not always antigen- or disease-specific and may not provide durable immunity. CDC keeps this on its agenda. CDC does not maintain the older non-vaccine CVX codes, many of which are not retired and are still used by some jurisdictions. CDC is interested in learning which jurisdictions report non-vaccine administrations and why.
