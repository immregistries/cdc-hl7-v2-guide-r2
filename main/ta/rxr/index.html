RXR Pharmacy/Treatment Route

Working analysis for the authors, from questions asked of AIRA's technical assistance service. Not part of the guide.

20 questions. Findings: none
Not yet assessed

What was asked

Questions about RXR concern whether and how the segment is returned in query responses, route coding in RXR-1 (the constrained NCIt-based value set versus HL7 Table 0162, legacy codes such as IN vs NS, and routes not in the list such as sublingual, intrauterine, G-tube, needle-free or "other"), and body site coding in RXR-2 (Table 0163 gaps for new administration sites such as JYNNEOS intradermal, oral vaccines, two-site administrations, and usage vs support status). The recurring theme is that the IG deliberately constrains route and site to immunization-relevant values, that RXR is RE (omit it entirely rather than send it empty or invalid), and that route/site are not critical to a complete immunization history.

IG clarifications suggested when the TA records were consolidated (5)
  • State explicitly that HL7 0162 route codes are accepted only for backward compatibility, and that RXR should be omitted when no NCIt route code applies (e.g., "Other").
  • Note in the route table that NS and IN are equivalent and indicate which is preferred.
  • Clarify the distinction between "Support Status" and field "Usage" in the IG.
  • Publish a table of valid RXR-1/RXR-2 combinations tied to BR-119.
  • Incorporate body site guidance for newer products (e.g., JYNNEOS scapula = RPC/LPC) and the rule that site is empty for oral route.

RXR Segment (general)

Does the RXR segment (route and site) need to be returned in Z32/Z42 responses? The functional guide says SHALL while the implementation guide says RE, and a health system wants route and site returned to use for vaccine matching.

Asked 2× · 2021–2022 · RSP · Answered · Related: RXR-1, RXR-2; Version & IG Interpretation; Query & Response Behavior

Answer given

RXR usage in the Z32 and Z42 RSP profiles is RE (IG p. 153), and this is consistent with the functional guide: RE means the system must send it if it is known, which corresponds to a SHALL support statement about system capability, not a requirement that it appear in every message. If the route is not known, no RXR segment should be sent; it is valid to send any immunization without an RXR. If known, route and site can be useful to clinicians and should be returned.

Separate the HL7 question from vaccine matching: the MIROW best practice on vaccination-level deduplication (vaccine matching) does not use route or site to decide whether two vaccinations match; it relies on date, vaccine type, trade name, lot number, administered/historical, and compromised dose status. So while RXR should be returned, it may not be useful for vaccine matching, and these data may be less trustworthy and could cause false matches/non-matches. In AART Q3 testing, 49 of 53 IIS returned RXR-1 and 51 of 53 returned RXR-2.

An IIS's RSP started failing NIST conformance (Query Measure 3) after it began returning RXR segments. What is wrong?

Asked 1× · 2024 · RSP · Answered · Related: RXR-1, RXR-2

Answer given

Returning no RXR segment was fine, but once RXR is returned it must be populated per the HL7 specification. In this test case the VXU sent to the IIS had no route/site data, so the IIS had no RXR data to return and the RXR segment should not be present at all rather than being sent empty or improperly populated.

RXR-1 Route

Why doesn't the IG support the full list of HL7 route codes?

Asked 1× · 2020 · VXU · Answered · Fields: RXR-1 · Related: Code Sets & Vocabulary

Answer given

The IG constrains the base standard to only those route codes used in an immunization context. EHRs and IIS should implement these constraints, and they are important for interoperability.

Answer given

When the route is "OTH" (Other), what should RXR-1 contain in an RSP? NIST expects an NCIt code, NCIt has no code for "Other", sending `OTH^Other^HL70162` fails, and RXR-1 is R.

Asked 1× · 2023 · RSP/VXU · Answered · Fields: RXR-1 · Related: RXR; Code Sets & Vocabulary

Answer given

The guide lists HL7 0162 values as a crosswalk for systems moving from the old values to the new ones. Only NCIt values may now be sent. Systems can keep accepting and processing HL7 0162 values, but should send only NCIt. The guide does not say so clearly, but if no NCIt value exists there is no route to send. RXR-1 is required, but the RXR segment is not. When RXR-1 cannot be valued, leave the RXR segment out.

An EHR lets providers record "Sublingual" and "Intranasal" routes, which are not in the CDC IG route value set. Can intranasal be mapped to nasal and sublingual to oral or other?

Asked 1× · 2021 · VXU · Answered · Fields: RXR-1 · Related: Code Sets & Vocabulary

Answer given

The CDC IG route list reflects how immunizations are actually administered in the US. A much larger set exists for other medications, but the guide doesn't support those values because IIS never expect to receive them. Intranasal means the same as nasal, so code it as nasal. Sublingual means dissolved under the tongue, and no vaccine is indicated for that route. The best fix is to remove or adjust these options in the product so users can't pick values that could be confused with the correct ones. For data already recorded, intranasal can safely be recoded as nasal for vaccines normally given in the nose, and sublingual can safely be recoded as oral for vaccines normally given by mouth. Otherwise, don't report the route if the data looks wrong. Route isn't critical to a complete immunization history, and leaving it out is better than sending bad data.

An EHR has a route of "Intrauterine" and a site of "Intrauterine". Should the route be mapped to something other than OTH, and how should the site be sent when Table 0163 has no "other" value?

Asked 1× · 2022 · VXU · Answered · Fields: RXR-1 · Related: RXR-2

Answer given

The IG purposefully constrains route of administration to values expected for vaccinations; many other medication routes exist but are not expected for immunizations, and new vaccination routes are added nationally when needed. Given current US vaccine products, intrauterine is not a valid route or site for vaccination, so this is most likely bad data (e.g., a wrong pick from an overly long list) rather than a mapping gap.

Options for the IIS include: (1) reject the message, at the risk of losing the vaccination event; (2) accept the vaccination but not store the route and return a warning about the invalid route; (3) accept the vaccination, drop the route, and not issue a warning; or (4) accept all data including the illogical route and address it through data quality processes outside HL7 (e.g., provider data quality reports). In any case the value is not valid for vaccination events.

Is G-tube (gastrostomy tube) a valid route of administration for immunizations, and is there an updated route code list?

Asked 1× · 2026 · VXU · Answered · Fields: RXR-1 · Related: Code Sets & Vocabulary

Answer given

G-tube is an acceptable route for select vaccines in limited circumstances, notably rotavirus (per Immunize.org Ask the Experts). An IIS could add support for the code representing this route: in HL70162 it is "GTT" (Gastrostomy Tube), and the NCIt code appears to be C65040, though that should be confirmed. Because actual use should be very low, it may not be worth the effort; assess how often it may be reported and whether the data is needed. If the IIS does not add support, the provider could send GTT/C65040 and the IIS could disregard it in processing (perhaps returning an informational error that the route is not supported), or the provider could send "OTH" (other).

Flagged when consolidated: Confirm the NCIt code for gastrostomy tube route (C65040 was stated as "appears to be"). Also note the suggestion to send "OTH" may conflict with the RXR-1 "Other" entry, which says only NCIt values may be sent and NCIt has no "Other" code.

RXR-2 Administration Site

Is RXR-2 (administration site) required? The CDC IG appears to list it as "Required", while AIRA data validation guidance says required but may be empty. Should an IIS require it for new administrations and make it optional for historical?

Asked 1× · 2024 · VXU · Answered · Fields: RXR-2 · Related: Version & IG Interpretation; Local Profiles & Jurisdictional Constraints

Answer given

RXR-2 has usage RE (Required, but may be empty) in the segment usage table of the HL7 2.5.1 Release 1.5 IG (page 129). Making it required would be a local requirement beyond the national IG, which may not be desirable for this element. The "Required" value seen elsewhere in the IG is from a different table whose column is "Support Status"; its footnote says support status indicates whether the field must be supported by the information system and messaged if known, not whether every message must contain it, which is indicated by the usage column. In short, support status is about whether the IIS should have a place to store the data; usage is about whether the sender must populate it or may leave it empty.

Where can one find which combinations of body site (RXR-2) and route (RXR-1) are valid, per data quality rule AIRA-DV-BR-119 (site and route cannot contradict)?

Asked 1× · 2022 · VXU · Answered · Fields: RXR-2 · Related: RXR-1; Data Quality & Validation

Answer given

The Immunization Action Coalition chart of vaccine administration route and site (https://www.immunize.org/catg.d/p3085.pdf) covers the majority of use cases. The caveat is that a clinician may intentionally deviate from it on a case-by-case basis (for example, chronic bleeding disorders as mentioned in the ACIP General Best Practice Guidelines). A provider consistently reporting doses out of alignment with the chart could indicate reporting errors or incorrect clinical practice.

Could an "Oral" concept be added to HL7 Table 0163 (administration site) since some vaccines are given by mouth?

Asked 1× · 2021 · VXU · Answered · Fields: RXR-2 · Related: RXR-1; Code Sets & Vocabulary

Answer given

Even if added to PHIN VADS it would not be in the IZ guide: when the route (RXR-1) is oral, the site (RXR-2) is to be left empty. A certified EHR should follow the guide; it can record both route and site internally, but when the route is oral it should report only the route, which may require custom programming. Adding the value nationally is unlikely because the install base is large and it would not improve data quality; it would only be worth it with evidence that many systems would benefit.

What body site codes should be used for JYNNEOS (mpox) alternative administration sites, such as intradermal at the scapula / below the scapula?

Asked 2× · 2022–2025 · VXU · Answered · Fields: RXR-2 · Related: RXR-1; Code Sets & Vocabulary

Answer given

Recommendations on body site codes for JYNNEOS were accepted at the Standards & Interoperability Steering Committee (SISC), and AIRA planned to publish a document describing the agreed funding and body site codes. For the alternative scapula administration site, use right posterior chest (RPC) or left posterior chest (LPC). These codes come from the base HL7 v2.5 Body Site table (HL7 Table 0163). Jurisdictions should check whether these values are available in their dropdowns/value sets.

A later (2025) question for data migration of doses recorded as "below scapula" was answered by pointing to the published document: AIRA's 2022 Mpox preferred select codes (2022_10_12_monkeypox_preferred_select_codes_final.pdf in the AIRA repository), which lists body site values for mpox vaccine administration including sites such as below the scapula.

Nirsevimab (Beyfortus) may be given as two injections, creating apparent duplicate administrations. Could Table 0163 add a "both" site value (e.g., both thighs) so the dose can be recorded once?

Asked 1× · 2025 · VXU · Partly answered · Fields: RXR-2 · Related: Patient Matching & Deduplication

Answer given

Early on it was understood that the two injections would be in two distinct body sites (e.g., left and right thigh), but this is not an absolute requirement. The injections must be at two different injection sites, which could be the same body site separated by at least one inch. So they may, but need not, be in different body sites, and a "both" body site value would not accurately cover all cases.

Rabies immune globulin is infiltrated around the bite wound with any remainder given IM at a distant site. How should two administration sites be documented, and should IIS support two sites for one administration? (A sender tried "wound", which is not valid.)

Asked 1× · 2023 · VXU · Answered · Fields: RXR-2 · Related: RXR-1

Answer given

There has been little community discussion on this. The IIS will never record 100% of what happens around a vaccination event; that is the role of the medical record. The IIS is designed for long-term storage of the essential vaccination history and a community-wide view of protection. Adding this level of detail would require a specific workflow and use case showing who would use the information and why, and would require both EHRs (which may not be able to send multiple sites) and IIS to change. The interim approach is to support a single administration site and work with senders accordingly; an IIS could add a local workaround value in its validation tables if needed. If a concrete use case emerges, it can be brought to the community.
