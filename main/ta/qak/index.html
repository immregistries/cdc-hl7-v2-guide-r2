QAK-2 Query Response Status

For a query test expecting a Z31 list of patients, is QAK-2 = OK correct when returning a list of possible matches, even though the response also had MSA-1 = AE with a warning ERR about an unrecognized city in QPD-8?

Asked 1× · 2026 · RSP · Answered · Fields: QAK-2 · Related: MSA-1, ERR, Conformance Testing & Validation Tools

Answer given

Yes, OK is correct. It is somewhat confusing because MSA-1 = AE indicates something was wrong with the query, but the IIS was able to cope and still execute it.

Which response profile and QAK-2 value apply to each query outcome? Is Z33 for no match, Z32 for a single high-confidence match, and Z31 for low-confidence or multiple matches, and what is used for too many matches?

Asked 1× · 2021 · QBP/RSP · Answered · Fields: QAK-2 · Related: MSH-21, Query & Response Behavior

Answer given

It depends on whether the query is history only (Z34) or history and forecast (Z44). Z33 is used for query fatal errors, no patients found, and too many matches, and also as the acknowledgment to a VXU; the query outcome is communicated in QAK-2. Z32 is for an exact match to a history-only query; Z42 is the exact-match response to a history-and-forecast (Z44) query. Z31 (list of candidate matches) is defined only for history-only queries; some IIS also use it for Z44, but that is beyond the standard and not required. Too many matches uses Z33 with QAK-2 indicating too many.

Summary: message rejection error -> Z23 with no QAK (both); processing error -> Z33 QAK-2 = AE; no match -> Z33 QAK-2 = NF; one match -> Z32 (Z34) or Z42 (Z44) with QAK-2 = OK; multiple matches below the maximum -> Z31 (QAK-2 = OK) or Z33 (QAK-2 = NF) for Z34, and Z33 (NF or TM) for Z44; more than the maximum -> Z33 with QAK-2 = NF or TM. This is adapted from AIRA's RSP MSA-1/QAK-2/ERR-4 guidance document; see also the IG response diagrams for Z34 (around p. 151) and Z44 (around p. 232).

Flagged when consolidated: The answer says Z33 is also used "as the acknowledgment to a VXU"; the VXU acknowledgment profile is normally Z23 (see the summary line and MSH-21 entries). Check the wording.

For a Z34 query with only patient sex (missing name and birth date), the IIS returned a Z33 with MSA-1 = AE and an ERR, but either omitted QAK/QPD or returned QAK-2 = AR. What response is expected?

Asked 1× · 2024 · QBP/RSP · Answered · Fields: QAK-2 · Related: MSA-1, ERR, QPD, Query & Response Behavior

Answer given

The expected response is a Z33 RSP that includes QAK and QPD, with QAK-2 (Query Response Status) = AE (application error). An earlier response missing QAK/QPD did not meet; after the IIS's fixes, one-off retesting showed a Z33 with MSA-1 AE, an ERR for the missing date of birth, and QAK/QPD present, which is close to passing, but QAK-2 was AR rather than the expected AE. Results also depend on when the IIS deployed fixes relative to when the assessment was generated.

Is a Z31 response appropriate when the result is TM (too many matches)?

Asked 1× · 2017 · RSP · Answered · Fields: QAK-2 · Related: Query & Response Behavior

Answer given

No. Per the IG and subsequent guidance document, a too-many-matches result should be returned as a Z33.

QAK-3 Message Query Name

When returning a Z31 to a Z34 or Z44 query, should QAK-3 echo the query name from the request (e.g., `Z34^Request Complete Immunization History^CDCPHINVS`) or represent the response profile?

Asked 1× · 2021 · RSP · Answered · Fields: QAK-3 · Related: QPD-1, MSH-21

Answer given

QAK-3 should echo what was in the query that was sent (the QPD-1 message query name). The response profile is identified in MSH-21 (e.g., `Z31^CDCPHINVS`). NIST's example shows MSH-21 = `Z31^CDCPHINVS` with `QAK|37374859|OK|Z34^Request Immunization History^CDCPHINVS` and QPD-1 = `Z34^Request Immunization History^CDCPHINVS`.
