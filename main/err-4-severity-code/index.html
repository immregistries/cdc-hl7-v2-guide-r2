ERR-4 conveys the severity of the issue described in an ERR segment, which drives the required follow-up action for that issue.

  • Information (I): A positive or neutral statement; no required follow-up action.
  • Warning (W): An issue that requires correction.
  • Error (E): An issue that requires correction and resubmission. An Error-severity issue may also be referred to as a "hard error" or "fatal error," reflecting that it results in rejection of the submitted VXU because core intent was not fulfilled.

Conformance statements

  1. SHOULDIIS SHOULD implement different validation rules based on the submitter or submitter class to align with operational priorities; for example, an issue treated as a Warning for general providers may be escalated to an Error for submitters subject to stricter program requirements (such as VFC participants).s1
  2. SHALLIIS SHALL return severity 'E' to convey that core intent was not fulfilled and correction and resubmission are required.s2
  3. SHALL NOTIIS SHALL NOT return severity 'E' for conformance violations alone (e.g., segment mis-ordering, missing required delimiters), unless the issue prevents the IIS from fulfilling core intent.s3
  4. SHALL NOTIIS SHALL NOT return severity 'E' for a requested update or delete action from a conformant VXU that was not applied (e.g., a deletion not honored due to policy).s4
  5. SHALL NOTSystems SHALL NOT automatically block the transmission or processing of subsequent messages for other patients or immunizations due to a severity 'E' error on one message.s5
  6. SHALLIIS SHALL return severity 'W' to convey an issue requiring correction that does not prevent core intent from being fulfilled.s6
  7. SHALLIIS SHALL return severity 'I' to convey an issue that does not require correction (e.g., a submitted precaution or VIS information that was not stored).s7
  8. SHOULDIIS SHOULD return severity 'I' to convey that a requested update or delete action from a conformant VXU was not applied.s8
  9. MAYIIS MAY return severity 'I' to convey a positive or neutral statement where no follow-up is required.s9
  10. SHALL NOTSystems SHALL NOT use informational-severity ERR segments to determine what data may need to be resubmitted.s10
