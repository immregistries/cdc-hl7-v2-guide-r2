5.11.3 Reinterpretation of Base-Standard Semantics

Quality review 1 warning

Findings from automated and editorial checks, for the authors. Not part of the guide.

  • Warning TAB System Entry Date/Time (RXA-22) Definition (Executive Summary; Table 1: RXA-22 definition): Missing. RXA-22 is not mentioned anywhere in the guide, and IGAMT has no definition for it. A submitter reading the HL7 base standard would send the first entry date, and an update would carry the same value as the original add.
    MissingAction: Narrative
    TAB For administered and historical immunizations, RXA-22 is the most recent date and time the immunization information was entered or updated in the submitting system. This replaces the base standard's reading (the date and time it was first entered), which some IIS do not follow because they use RXA-22 for matching and deduplication.
    Recommendation Add the TAB's definition to 4.6 (Immunization Information), for example in 4.6.4 next to updates: "For administered and historical immunizations, RXA-22 is the most recent date and time the immunization information was entered or updated in the submitting system." List it in 5.11.3 (Reinterpretation of Base Standard Semantics), since it differs from the base definition.

    See the TAB comparison

    qf-tab-rxa22-01

A number of fields have taken on new, domain-specific meaning within IIS implementations:

RXA-9 now indicates administered vs historical vaccinations, or vaccine event record type, becoming a critical driver of business logic.

RXA-11 is consistently used to identify the administering organization rather than a physical bed or room location.

These reinterpretations are mature, universal, and non-negotiable. Aligning them back to the original semantics is neither feasible nor beneficial.
