4.6.4.5 Inventory and Accountability Considerations

Quality review 5 notes

Findings from automated and editorial checks, for the authors. Not part of the guide.

  • Note MIROW guide Decrementing Inventory via Electronic Data Exchange (BR204, S501 to S503, S1001 - Lot problems): Partly covered. The ACK rules give the right answer: the vaccination was recorded, so the VXU is accepted, and an issue that needs correction is a Warning. ERR-5 has codes for some of these cases: 2001 (expired vaccine administered), 2011 (lot not valid for the vaccine), and the general 2601 (inventory management error). But the guide never says that an inventory problem is reported this way. Submitters cannot tell from the guide whether a dose was decremented. Inventory and Accountability Considerations covers corrections only.
    Partly coveredAction: Narrative
    Best practice Only active inventory is decremented. When the lot in a submission is expired, inactive, at zero balance, or not in the provider's inventory at all, the vaccination is still recorded (as non-viable if the lot had expired), the dose is not decremented, and the IIS notifies the provider organization or EHR. P07 lists the ACK as one way to notify, alongside reports and the user interface.
    Recommendation Add to Inventory and Accountability Considerations that when a vaccination is recorded but inventory cannot be decremented (lot not found, inactive, expired, or at zero balance), the IIS SHOULD return a Warning with ERR-5 2601, or a more specific code such as 2001, so the submitter can correct the lot or account for the dose (MIROW BR204, P07).

    See the MIROW comparison

    qf-mirow-di-12
  • Note MIROW guide Decrementing Inventory via Electronic Data Exchange (BR205, S1203, S1204 - Changes after a closed reconciliation): Reworded. The guide allows local policy to delay or review a correction "when inventory or accountability records can no longer be reconciled". The ACK says whether it was applied and whether manual follow-up is needed. An update or delete not applied for policy reasons is reported as Information, not as an Error. One consequence is not spelled out: correcting an identifying field such as RXA-3 means a delete followed by an add, which reverses and repeats the decrement and so can reach into a closed reconciliation period.
    Reworded
    Best practice The IIS should not decrement automatically when the vaccination date falls on or before the end of the most recent closed reconciliation. A delete or a late vaccination for a closed period needs the reconciliation to be reopened by IIS staff, and an issue is logged for manual work.

    See the MIROW comparison

    qf-mirow-di-17
  • Note MIROW guide Immunization Information System Inventory Management Operations (BR718, PM07 - Flag doses that do not match the inventory): Partly covered. The guide's ACK rules support this, but the guide does not say that an unmatched lot is reported. This is the same gap as mirow-di-12.
    Partly coveredAction: Narrative
    Best practice When a dose reported by an EHR cannot be matched to a lot in the provider's inventory, the IIS must flag the discrepancy to the provider organization, preferably immediately and in any case before the reconciliation period closes. The submitter of HL7 data should have good visibility of reported vaccinations that did not match known lots, and a simple process to resolve them.
    Recommendation Covered by the recommendation in mirow-di-12, which should cite MIROW 2012 BR718 as well as the 2016 guide.

    See the MIROW comparison

    qf-mirow-im-13
  • Note Narrative uses "is required", which reads as a requirement. If it is one, state it as a conformance statement; otherwise consider softer wording.
    Local policy may require review or delay application when inventory or accountability records can no longer be reconciled. In those situations, the acknowledgment behavior described above communicates whether the correction was applied and whether manual follow-up is required.
    qf-normative-prose-54f76c37
  • Note SISC guidance Guidance on Unit of Sale/Unit of Use Lot Numbers (Notes: Matching, Reconstituted Vaccines, and Regular Expression): Out of scope. The guide deliberately "does not prescribe an IIS's internal inventory or lot-validation workflows", so this is IIS operations. Its inventory section would still benefit from a link to this guidance and to the MIROW inventory guide.
    Out of scopeAction: Narrative
    Guidance Mapping a unit-of-sale lot to a unit-of-use lot is simple, but the reverse is not (except for Menveo). An IIS that knows a provider's inventory can usually match a reported unit-of-use lot to that provider's single unit-of-sale lot, and resolve any discrepancies during reconciliation (see the MIROW guide on decrementing inventory via electronic data exchange).
    Recommendation In the inventory section, link this guidance and the MIROW guide on decrementing inventory (see the MIROW alignment proposal).

    See the SISC guidance comparison

    qf-sisc-lot-02

Corrections to administered vaccinations can affect inventory decrementing, vaccine accountability, and program reporting. These operational consequences do not create a different HL7 correction model. When inventory records can be reconciled automatically or manually, the IIS can apply the vaccination correction and make the corresponding inventory adjustment.

Local policy may require review or delay application when inventory or accountability records can no longer be reconciled. In those situations, the acknowledgment behavior described above communicates whether the correction was applied and whether manual follow-up is required.
