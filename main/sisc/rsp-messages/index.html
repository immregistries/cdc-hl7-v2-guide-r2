SISC guidance · June 2017

Guidance for HL7 RSP Messages to Support Interoperability

How to populate the acknowledgment code (MSA-1), the query response status (QAK-2), and error severity (ERR-4) in a query response so that all three agree with each other and with the outcome of the query.

Published PDF · Copy in this repository

Summary

The guide keeps this guidance's outline of query outcomes (rejected, failed, processed) in its RSP profile sections and figure 17, but it drops the field-level rules that were the point of the guidance. Its MSA-1 and ERR-4 rules are written for VXU acknowledgments only, and it never says how to populate MSA-1 or QAK-2 in a query response, apart from TM for too many matches. The guidance also uses MSA-1 'AE' with ERR-4 'E' for a query that fails, which the guide's new ACK model forbids for VXUs. CDC should decide whether that model applies to query responses. The one change the guide makes on purpose (a Z31 may answer a Z44 query) comes from the Query Response Flexibility TAB.

Requirement by requirement

The guidance saysResultIn the guide

Caveats p. 1

The ERR-4 severity definitions in the ACK guidance (Error, Warning, Information) also apply to query responses.		Partly covered Warning

The guide defines the ERR-4 severities only in terms of a VXU and its core intent ("results in rejection of the submitted VXU because core intent was not fulfilled"). Nothing says the same severities apply to an RSP, or what "core intent" means for a query.

Recommendation: State that the ERR-4 severities apply to query responses as well, and say what an Error means for a query (the query could not be executed and must be corrected and resent).

Action: Narrative

3.3.3.2 ERR-4: Severity Code, 3.3.3.2 s2, 3.3.3.2 s6, 3.3.3.2 s7

Caveats; Summary p. 1, 3

An RSP^K11 message may contain only a single ERR segment. When several errors are found, the responding system selects the most salient one to return.		Partly covered Note

The IGAMT RSP profiles allow ERR [0..1], as the base standard requires, so the limit is enforced. The narrative never mentions it, or says which error to return when there are several. Readers who know the ACK (which allows many ERR segments) will not expect the difference.

Recommendation: Add a sentence to the RSP profile sections: an RSP carries at most one ERR segment, so the IIS returns the most significant issue.

Action: Narrative

3.5.2.4 Z33 - Return a Response with No Person Records, 3.5.2 RSP Response Profiles

Query Response Guidance (message is rejected) p. 2

The message is rejected when it has an unsupported message type or event code (MSH-9), an unsupported processing ID (MSH-11), or an unsupported version ID (MSH-12), or cannot be processed for reasons unrelated to format or content. The Z23 (ACK) profile is the response.		Partly covered Warning

The guide's Z23 section describes the same outcome more broadly ("malformed or invalid MSH/QPD segments, missing required message header information, or other unrecoverable errors detected prior to query execution"), and figure 17 shows it as "Structurally valid? No". It does not name the four MSH conditions. The fifth condition, "unrelated to format or content", is one the guide removes as a reason for 'AR' on a VXU (following the ACK TAB), because it describes a transport problem. The guide does not say whether it is also removed for queries.

Recommendation: Name the MSH conditions that lead to a Z23, and say that, as for VXUs, a transport or connectivity problem is never reported with a Z23.

Action: Narrative

3.5.2.1 Z23 - Return an Acknowledgement, Figure 17, 3.3.4.1 MSA-1 Guidance

Query Response Guidance (message is rejected) p. 2

must In a Z23 sent in response to a query, MSA-1 must be AR, an ERR segment must be present, and ERR-4 must be E (the sender should correct the issue and resubmit).		Missing Warning

The Z23 section says the IIS "is unable to execute the query" but not what MSA-1 and ERR-4 contain. The guide's MSA-1 rules ('AR' when there is a severity 'E' error) are written for a VXU ("SHALL be returned to convey VXU rejection"). The IGAMT Z23 profile allows either a Q11 or a V04 trigger, so the same profile serves both, but only the VXU case is described.

Recommendation: In the Z23 section, state that a Z23 sent in response to a QBP has MSA-1 'AR' and one ERR segment with ERR-4 'E'.

Action: Narrative

3.5.2.1 Z23 - Return an Acknowledgement

Query Response Guidance (error prevents the query) p. 2

must When the message is accepted but an error prevents the query from being executed, the response is a Z33 with MSA-1 'AE', QAK-2 'AE', and ERR-4 'E'. QAK-2 may not be AR (reserved for the Z23 conditions) or OK, TM, or NF (which report a query that was executed).		Missing Warning

The guide's Z33 section lists only no match, policy limits, and consent restrictions, and says that a Z33 means the IIS "has processed the query". Figure 17 has no path for a query that is accepted but cannot be executed. The combination this guidance requires also conflicts with the guide's new ACK model: for a VXU the guide says MSA-1 'AE' SHALL NOT be returned with a severity 'E' error, and that 'AE' means a qualified acceptance. If that model applies to query responses, a failed query would get MSA-1 'AR'; if it does not, the guide needs to say so.

Recommendation: CDC to decide how a query that cannot be executed is reported: Z33 with MSA-1 'AE' as in this guidance, or Z33 (or Z23) with MSA-1 'AR' to match the ACK model. Then add the outcome to the Z33 section and to figure 17, with the QAK-2 value ('AE').

Action: CDC decision

3.5.2.4 Z33 - Return a Response with No Person Records, Figure 17, 3.3.4 MSA-1: Derivation of Message-Level Disposition

Query Response Guidance (query is successfully processed) p. 2

A query that runs to completion is successful, however many patients it finds (none, one, or more than one). The Z31, Z32, Z33, or Z42 profile is used depending on the query profile and the outcome.		In narrative only Note

The guide describes the response profiles as the "controlled set of outcomes" of matching, and its Z33 section says that a Z33 means the IIS "has processed the query". It does not say outright that finding no patient, or several, is a successful query rather than an error.

3.5.2 RSP Response Profiles, Figure 17, 3.5.2.4 Z33 - Return a Response with No Person Records, 3.5 Response (RSP) Profiles

Query Response Guidance (query is successfully processed) p. 2

will; may MSA-1 is 'AA' when there are no errors (no ERR segment), and may also be 'AA' with an ERR segment whose ERR-4 is 'I'. MSA-1 is 'AE' when there are errors that do not prevent the search from completing; the ERR segment then has ERR-4 'W', and ERR-4 may not be 'E'.		Missing Warning

3.3.4 MSA-1: Derivation of Message-Level Disposition, 3.3.4 s1, 3.3.4 s2

Query Response Guidance (query is successfully processed); Summary p. 3

should; may not QAK-2 reflects the outcome of the search and is independent of MSA-1, which reports the technical processing of the message. In a successful query, QAK-2 may not be 'AR' or 'AE'.		Missing Warning

The guide never explains QAK-2 or how it relates to MSA-1. The only QAK-2 value it names is 'TM', in the Z31 section. The IGAMT profiles bind QAK-2 to HL70208 (OK, NF, TM, AE, AR) but set no rule linking it to the outcome or to MSA-1.

Recommendation: Add a short section, or a table like this guidance's Table 2, on QAK-2: what each value means, which values go with which response profile, and that QAK-2 and MSA-1 are set independently.

3.5.2.2 Z32 - Return Complete Immunization History, 3.5.2.5 Z42 - Return Evaluated Immunization History and Forecast, 3.5.2.4 Z33 - Return a Response with No Person Records, Figure 17

Summary (Table 2) p. 3

Multiple matches (fewer than the maximum allowed): to a Z34 query, Z31 with 'OK' or Z33 with 'NF'; to a Z44 query, Z33 with 'NF' or 'TM'.		Conflict Note

The guide lets a Z31 answer a Z44 query as well, following the Query Response Flexibility TAB (January 2024), which replaced this part of the guidance. This change is intended. The IGAMT Z31 profile still requires QPD-1 'Z34', a conflict recorded in the TAB comparison (tab-qrf-04). The guide also does not give the QAK-2 value for a Z31 ('OK').

Recommendation: Record in the change history that a Z31 may now answer a Z44 query, replacing this guidance, and give the QAK-2 value for a Z31.

Action: Narrative

3.5.2.3 s1, 3.5.2.3 Z31 - Return a List of Candidates

Summary (Table 2, footnote 1) p. 3

More than the maximum number of matches: Z33 with 'TM' (preferred, as it is most specific) or 'NF' (where local law, policy, or regulation prevents indicating that several patients match).		Partly covered Warning

The Z31 section says that an IIS with too many candidates "returns a QAK-2 value of TM" rather than an oversized Z31, but does not say which response profile carries it (Z33), and does not allow 'NF' where policy forbids revealing that several patients match.

Recommendation: Say that too many matches is reported with a Z33 and QAK-2 'TM', or 'NF' where local law or policy does not allow the IIS to reveal that several patients match.

Action: Narrative
