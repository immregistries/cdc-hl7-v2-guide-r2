2.5.2 Transport-Level vs Message-Level Responses

Message exchange between submitting systems and an IIS operates across two distinct layers, each communicating a different kind of information.

The transport layer manages the delivery of a message from the submitting system to the IIS. A successful response at this layer, such as a positive SOAP response, confirms only that the message reached the IIS interface, but says nothing about whether the IIS accepted or processed the message's content. When a transport-level problem occurs (for example, a network outage, invalid credentials, or an endpoint error), it is reported as a SOAP Fault as defined by the CDC WSDL. Because this is a connectivity issue rather than a content issue, retry behavior, connection recovery, and related transmission handling are transport-layer concerns addressed in the CDC WSDL documentation, not in this acknowledgement guidance.

The HL7 application layer operates only after a message has been successfully delivered, and communicates the outcome of processing that message's content. For VXU submissions, this outcome is communicated through an HL7 v2 ACK message, indicating whether the message was accepted, accepted with warnings, or rejected due to data issues. Because VXU submissions make up the majority of acknowledgement scenarios, the acknowledgement guidance that follows focuses primarily on ACK behavior in this context.

Query interactions follow a different pattern. A QBP message normally receives an RSP response rather than an ACK, since the RSP itself carries the outcome of the query. An ACK is generated for a query only in the exceptional case where the QBP message is malformed or otherwise cannot be processed, and therefore cannot generate a valid RSP.

It's worth noting what an HL7 v2 acknowledgement is not: it is not an instruction about whether to continue or pause the transmission of subsequent messages. An acknowledgement speaks only to the outcome of the specific message it responds to. Any question of whether transmission should continue in the face of connection issues belongs to the transport layer described above, not to the meaning of an individual acknowledgement.

Understanding this layered relationship, transport confirming delivery, and HL7 v2 acknowledgements confirming processing outcome, provides the necessary foundation for the detailed acknowledgement conformance requirements that follow.
