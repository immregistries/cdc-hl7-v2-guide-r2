Summary

Section 6.2 restates most of the Overview: purpose, scope, SISC approval, intended use, and optional functionality. Three things are missing. The guide does not say how TABs relate to this release: which TABs it folds in, whether they still apply once it is published, which wins when they differ, and that new TABs will build on this guide. It does not define the R, P, and E usage of codes in a value set, which IGAMT and several TABs use. And it does not say that implementers also review local guides, or how to get involved.

Overview; relationship to the National IG p. 1

TABs "build on and further clarify" Release 1.5 (2018), and will inform the next version of the guide.		Missing Warning

Section 6.2 describes TABs in general and says their content "is incorporated into future versions", but not what that means for this release. A reader cannot tell which published TABs this guide incorporates, whether those TABs still apply after it is published (for example, to systems still on Release 1.5), which document wins where they differ (this comparison found several conflicts), or that new TABs will build on this guide.

Recommendation: Add a card to 6.2, after 6.2.5, along these lines: "This guide incorporates the TABs published through [month year], listed in [appendix]. For systems implementing this guide, it replaces those TABs; where a TAB and this guide differ, this guide applies [and the difference is listed]. The TABs remain in effect for systems still implementing Release 1.5. TABs published after this guide build on it, and are incorporated into the next release." CDC and SISC decide the supersession rule and the cut-off date.

Intended Use p. 1

SHALL Implementers SHALL use TABs to develop and maintain interfaces. Unless otherwise indicated, organizations SHALL use TAB specifications as soon as feasible, working with exchange partners to test or confirm changes.		Covered

The guide's statement leaves out "unless otherwise indicated" and working with exchange partners to test changes.

Intended Use (optional functionality) p. 1

MAY, SHALL Some TABs specify new optional functionality. Organizations MAY support it as local or federal policy requires; if they do, they SHALL implement it as the TAB specifies.		Covered6.2.3 Intended Use of TABs, 6.2.4 Handling of Topic-Specific TABs

Intended Use (policy) p. 2

Policy decisions and regulatory requirements are outside the scope of TABs.		Covered6.2.2 Scope of TABs

Conformance (Table 1) p. 2

Conformance verbs SHALL, SHOULD, MAY, MAY NOT, SHOULD NOT, and SHALL NOT, as defined in HL7 Version 2 Conformance Methodology, Release 1 (September 2020).		Reworded Note

Section 1.5 defines the same verbs except MAY NOT, and does not cite the HL7 Conformance Methodology. Its SHOULD ("may deviate based on local policy, technical constraints, or phased implementation") says more than the TAB's "Recommended to implement", but does not conflict with it.

Recommendation: Cite the HL7 v2 Conformance Methodology in 1.5, and add MAY NOT or say that the guide does not use it.

Action: Narrative

1.5 Conformance Verbs

Value set specifications (Table 2) p. 2

TABs can give the usage of each code in a value set: R (Required, the code SHALL be supported), P (Permitted, to be specified locally), and E (Excluded, the code SHALL NOT be supported).		Missing Warning

The guide defines element usage (R, RE, C, O, X) and value set extensibility, but not code usage within a value set. IGAMT gives code usage throughout (for example ASN as E in HL70201_IZ01), and the Phone and Email TAB relies on it.

Recommendation: Add the TAB's Table 2 to 4.3 (Dynamic and Fixed Code Sets), and say that the value set tables give code usage.

Action: Narrative

Local implementation guidance p. 3

SHALL Implementers SHALL also review the local implementation guides published by jurisdictions, which further constrain national specifications.		Partly covered Note

The guide says each IIS SHOULD publish a local guide and that local profiles SHALL NOT contradict this one, but not that implementers review local guides.

Recommendation: Add to 1.1.2 (Scope): "Implementers SHALL review the local implementation guide of each IIS they exchange with."
