The CDC Core Data Elements for Functional Standards (CDEs) are the baseline set of data elements that CDC has identified as essential to IIS functionality, ensuring the completeness of patient and vaccination records for each vaccination event. CDEs are documented in the CDC Core Data Elements (CDE) for Functional Standards resource, which provides definitions, rationale, and standards mappings for each element. Each CDE is mapped to a corresponding HL7 v2.5.1 field or component, meaning that the HL7 messaging conformance defined throughout this guide is, in large part, the mechanism by which CDEs are actually captured, transmitted, and exchanged between systems. This guide focuses on that HL7 messaging conformance and does not restate the full CDE catalog, definitions, or rationale, which are maintained in the CDE resource itself [3].

Each CDE must be supported by several key functions within an IIS: facilitating input, processing, validation, updates, and deletion to maintain data accuracy and consistency; secure storage to guarantee accessibility and preservation for future use; and, where needed, generation or transformation of CDEs, such as creating unique identifiers or combining data. Many of these functions are expressed directly in this guide's HL7 conformance requirements: for example, a CDE's usage designation (R, RE, O, etc.) reflects expectations for how consistently that element should be populated in a VXU, and specific HL7 fields such as MSH-4, PID-7, and RXA-3 exist precisely to carry designated CDEs across systems in a standardized way.

CDEs represent a baseline, not a ceiling. They establish the basic structure of data that should be contained within an IIS, but are not prescriptive regarding naming conventions, repetition frequency, or how the data is used locally. IIS and their data exchange partners may support additional data elements beyond this baseline as needed.

Some CDEs constitute Critical Data for the purposes of VXU processing and acknowledgement messaging, as described in the Acknowledgement Message Profile section. Because CDEs are carried through specific HL7 fields, the presence, absence, or validity of those fields in a submitted VXU directly affects whether the message fulfills its core intent and is accepted or rejected. Understanding the CDE catalog provides useful context for why certain HL7 fields carry this level of operational significance throughout the rest of this guide.
