4.3.6 Local Extensions and Coordination

Local extensions introduce operational risk if not coordinated and communicated. While some value sets explicitly allow extension, doing so requires publication, partner awareness, and ongoing governance to prevent fragmentation.

Certain code systems provide formal extension rules (e.g., funding eligibility), while others rely on drawing from a broader canonical set (e.g., race codes). In all cases, local extensions must coexist with national expectations rather than replace them.

Conformance statements

  1. SHALLSystems (including submitting systems and IIS) SHALL document and publish any supported local extensions to open value sets.s1
  2. SHOULDSystems SHOULD provide advance notice to trading partners when introducing new locally defined values.s2
  3. SHALL NOTLocal extensions SHALL NOT override or redefine nationally defined values.⚑s3
  4. SHOULDSubmitting systems SHOULD coordinate with IIS before using locally extended codes in production exchange.s4
  5. SHALLQuerying systems SHALL be capable of handling locally extended values in responses and SHALL not assume that only nationally defined codes will be returned.⚑s5
