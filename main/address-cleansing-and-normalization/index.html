4.5.3.6 Address Cleansing and Normalization

Quality review 1 note

Findings from automated and editorial checks, for the authors and reviewers. Not part of the guide.

  • Note 5 requirements were written as paragraphs in the draft and are shown here as conformance statements (wording unchanged): s1, s2, s3, s4, s5.qf-statement-from-paragraph-ef50cf7b

Address cleansing services allow IIS to improve data quality without imposing brittle validation rules on submitters. These services can normalize formats, correct typographical errors, and supply missing attributes such as county codes or ZIP+4.

Cleansed addresses are typically more suitable for matching, de-duplication, and mapping than raw submitted values.

Conformance statements

  1. SHOULDIIS SHOULD use a third-party address cleansing service to normalize and validate address data.s1
  2. SHALL NOTIIS SHALL NOT require strictly coded state, country, or county values at submission.s2
  3. MAYIIS MAY retain both the original submitted address and the cleansed address.s3
  4. SHOULDIIS SHOULD use the cleansed address for matching, de-duplication, and geocoding.s4
  5. SHOULDIIS SHOULD return the standard two-letter USPS state abbreviation (for example, 'AK' for Alaska) for U.S. addresses in outbound responses to improve automated interoperability.s5
