4.6.4.2 Submitter Correction Behavior

Quality review 2 notes

Findings from automated and editorial checks, for the authors. Not part of the guide.

  • Note MIROW guide Decrementing Inventory via Electronic Data Exchange (Chapter 9 - Action codes and the vaccination ID): Guide adds. The guide provides that standard of practice. Submitters SHALL support A, U, and D, reuse the source record's ORC-3, and use a delete and add only when an identifying field changes. IIS treat source and ORC-3 as high-confidence evidence while still matching.
    Guide adds
    Best practice (In 2016 MIROW found that best practice for action codes was not documented, that many EHRs send only "A", and that it was not known whether ORC-3 was populated reliably. It recommended examining both "in more depth in the future to develop a standard of practice".)

    See the MIROW comparison

  • Note Statement s5 Its subject is "Delete", not a system or party, so it is unclear who must comply. Naming the responsible party (for example, "Submitting systems SHALL …" or "IIS SHALL …") makes the requirement testable.qf-no-actor-920dffe0

An update refers to the same source record and carries the same ORC-3. A delete also refers to the original source record and carries the ORC-3 and identifying field values previously submitted for that record. When a rechart creates a replacement source record, the replacement add carries the identifier assigned to the replacement record.

Changes to fields outside the identifying fields list can be sent as updates. The correction message can include other current vaccination information even when those additional fields did not trigger the correction.

Conformance statements

  1. SHALLSubmitting systems SHALL support sending adds (A), updates (U), and deletes (D) for vaccination records.s1
  2. SHALLWhen any identifying field changes, submitting systems SHALL send a delete followed by an add containing the corrected vaccination information.s2
  3. SHALLWhen only non-identifying field data changes, submitting systems SHALL send an update.s3
  4. SHALLSubmitting systems SHALL reuse the source record’s ORC-3 in every update or delete that refers to that record.s4
  5. SHALLA delete SHALL carry the identifying field values previously submitted for the source record being deleted.⚑s5
