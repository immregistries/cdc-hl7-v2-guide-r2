In HL7 v2 messages, data types define the structure and format of fields and their components. Value sets and code systems are separate enumerations applied within coded fields; they are not data types themselves. See Section 7.3, Data Types, for the formal HL7 v2 data type taxonomy and Section 7.4, Value Sets, for the ValueSets and authoritative field-to-value-set mappings.

- **Primitive (simple) data types** are unstructured or atomic values used to represent a single piece of information, such as a string or text value (e.g., patient name, street address), a numeric value (e.g., administered dose amount, birth order), or a date/time value (e.g., date of birth, administration date, message sent date).
- **Composite (complex) data types** are composed of multiple components, each with its own data type. Coded data fields are one example, using data types such as CE or CWE to represent coded elements. The specific code set applied to a given CE or CWE value is determined by the field definition itself, not by the CE/CWE data type; for instance, a field may require CVX codes to represent vaccine type.
- Common code systems and value sets referenced in coded fields include CVX (Vaccination Codes) and NDC (National Drug Codes), and the authoritative mapping of which code system applies to each field is documented in Section 7.4, Value Sets, and in the profile field tables (see Section 7.1). XPN (Extended Person Name) is another example of a composite data type, including components such as family name (FN), given name, and name type, where FN is itself a data type.
- **Special-purpose data types** serve specific, narrow purposes within HL7 messaging. Examples include VID (Version ID), used to represent version identifiers, and HD (Hierarchic Designator), used to represent system, facility, or namespace identifiers.
