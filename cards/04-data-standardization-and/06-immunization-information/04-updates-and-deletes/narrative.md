Vaccination records require correction when information changes or when a previously reported record is retracted. Submitting systems know which local vaccination record changed and express that intent through RXA-21 and ORC-3. IIS maintain consolidated vaccination histories and determine how an incoming correction relates to records already stored. Reliable correction therefore depends on both consistent source identifiers and vaccination-level matching. IIS policy can also require manual review or restrict changes to records reported by another organization.

Two correction workflows are common. In an update workflow, the submitting system modifies the same source record and continues to use the same ORC-3. In a rechart workflow, the submitting system deletes the original source record and creates a replacement record. The delete refers to the original source record, while the replacement add carries the identifier assigned to the replacement record. Both workflows can represent a legitimate correction.

Production support for source-specific ORC-3 matching is not yet consistent enough to make ORC-3 the only mechanism for locating a vaccination record. The correction rules below therefore preserve the current field-based safety model. As source-specific ORC-3 associations become broadly available and dependable, a future version of the guide can simplify these requirements and reduce dependence on repeating prior matching information.
