This section explains how use cases and messaging profiles work together to support the immunization data exchange workflows addressed by this guide. At a high level, the primary use cases focus on two essential needs: submitting administered and historical immunizations to the IIS to maintain a complete record, and retrieving a consolidated immunization history and forecast for use in clinical decision making. Supporting these core interactions are additional profiles that confirm receipt and processing of submissions and enable reliable querying, including patient matching, which is inherently complex and jurisdiction-specific.

A use case represents a real-world scenario involving one or more actors and the actions they perform. For example, a submitting system may report a new vaccination to an IIS, or a querying system may request a patient's consolidated immunization history. Each use case describes a specific functional interaction that must be supported across systems.

A profile is a set of conformance requirements-rules layered on top of the base HL7 v2 message structures-to meet the needs of a particular use case. The HL7 v2 standard is intentionally flexible; this guide narrows that flexibility by defining specific expectations for each profile so that messages are interpreted consistently across jurisdictions and systems. The same HL7 v2 segments and data elements may appear in multiple profiles but with different requirements, and implementers must always interpret requirements within the context of the declared profile. Indicating the correct profile within a message signals which constraints apply and enables validation and testing tools to apply the appropriate rules.

The query and response patterns defined in this guide also support related use cases such as access by patients, schools, and other public health programs, to the extent that those interactions align with the standard IIS query model. This guide does not attempt to cover all HL7 messaging used by IIS. Use cases such as IIS-to-IIS exchange, bulk data sharing, or patient demographic updates (for example, ADT-driven workflows) have distinct considerations and are outside the scope of this document. Other HL7 messages and profiles may be implemented by IIS as needed; this guide neither prescribes nor restricts those implementations.
