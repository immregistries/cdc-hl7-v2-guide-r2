Some changes update descriptive or supporting details of a vaccination record without changing the identity of the vaccination event itself. These changes are intended to refine or correct information about an already reported vaccination, not to replace it or introduce a new event.

When only non-identifying fields are modified, the update should be interpreted as applying to the previously submitted vaccination record. Changes such as correcting a lot number, adjusting manufacturer information, or updating ancillary details SHOULD NOT, by themselves, cause the IIS to treat the vaccination as a new or distinct event. The purpose of an update in these cases is to improve data quality while preserving continuity of the vaccination record.

Submitting systems signal this intent by sending a VXU update rather than a delete-and-add sequence. IIS are expected to apply these updates to the existing vaccination record and to avoid creating duplicate immunization events solely as a result of non-identifying field changes.

Passive access to a vaccination record, such as viewing or opening the record without modifying any identifying or non-identifying fields, does not represent a meaningful change and should not result in a VXU message. Submitting systems SHOULD ensure that VXU updates are generated only when actual changes to vaccination data occur, and that multiple transient or intermediate system actions are not reported as separate updates. Sending VXUs when no substantive changes have occurred wastes resources and can create processing ambiguity, particularly when messages are received and applied in rapid succession. VXU submissions in this scenario SHOULD be suppressed unless there is a final, material change that the IIS needs to reflect.
