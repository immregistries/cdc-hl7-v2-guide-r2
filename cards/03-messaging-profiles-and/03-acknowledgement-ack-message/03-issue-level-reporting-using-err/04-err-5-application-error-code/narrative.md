ERR-5 communicates the specific nature of an issue using a code from a national code set, supplementing ERR-2 (location) and ERR-4 (severity) by answering the question of what the problem was. Codes are organized into ranges by issue type, including legacy HL7 v2 codes, conflicting data, inappropriate data, invalid data, lookup failures, message construction issues, missing data, processing errors, data sharing or consent restrictions, and missing or invalid endorsed data elements, among others. Codes in the missing- and invalid-data ranges use matching endings to pair each data element across both ranges.

Implementing a code means that when the IIS detects the corresponding condition, it returns that code in ERR-5. This does not, by itself, determine how the underlying data is treated (e.g., whether it is accepted or rejected) or what ERR-4 severity is assigned; those determinations remain governed by local policy and are conveyed independently through ERR-4.

If a concept needed by an IIS is not already represented in the national code set, implementers should coordinate with the guide's maintaining organization to have a new code added, rather than defining a local code. Locally invented codes are discouraged, as they increase burden and inconsistency across interfaces. Submitters should expect that the national ERR-5 code set will continue to expand as new data quality concepts are identified.
