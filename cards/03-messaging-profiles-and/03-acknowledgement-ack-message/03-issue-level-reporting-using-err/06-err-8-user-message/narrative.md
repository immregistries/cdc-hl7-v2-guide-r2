ERR-8 provides a human-readable explanation of the issue described in an ERR segment, intended for end users such as clinical or operational staff rather than interface developers. Therefore, plain, non-technical language should be used.

ERR-8 should not duplicate information already available in ERR-2, ERR-4, or ERR-5; severity and disposition are already conveyed through ERR-4 and MSA-1, respectively, so phrases like "Required field" or "Message rejected" are unnecessary in ERR-8. For example, "Patient first name is missing" is appropriate; "PID-5.2 is not populated" is not.
