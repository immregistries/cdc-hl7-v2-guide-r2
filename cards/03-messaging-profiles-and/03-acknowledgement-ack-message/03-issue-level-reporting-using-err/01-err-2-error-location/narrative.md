ERR-2 identifies the specific location in the message where an issue was identified. When populated, it SHALL indicate a single location for understanding and resolving the issue, using the HL7 v2 ERL data type format rather than commonly used shorthand. For example, the field commonly referred to as "PID-5" is expressed in ERR-2 as PID^1^5.

ERR-2 should point to the most helpful location for resolving the issue. For repeating segments, such as multiple RXA or OBX segments, it is especially important to identify which repeat the error applies to. When an issue involves multiple fields, for example, a vaccination date that precedes the patient's date of birth, ERR-2 can reference only one location per segment. In these cases, a single ERR segment may point to the most relevant field, with the conflict explained in ERR-5 or ERR-8, or two ERR segments may be returned, each referencing one of the fields involved. When an issue results from an entire segment being absent, such as a missing OBX, ERR-2 cannot point to the missing segment directly and should instead reference the segment group in which it would have appeared, for example, the associated ORC segment.

If an issue is not tied to a specific segment or field, such as "Patient not consented" or a message-level confirmation, ERR-2 should be left blank. ERR-2 is an RE field, and it is valid to omit it when there is no specific location to reference.

Accurate use of ERR-2 enhances the interpretability of ACK messages for technical and clinical users alike, supports efficient troubleshooting, and helps ensure that data quality issues can be precisely identified and resolved.
