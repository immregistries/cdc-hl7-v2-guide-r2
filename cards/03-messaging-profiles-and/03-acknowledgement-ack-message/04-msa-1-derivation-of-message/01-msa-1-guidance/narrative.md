Per these specifications, an MSA-1 value of 'AE' indicates the VXU was accepted as a qualified successful transmission. Previously, interpretation of 'AE' was ambiguous, requiring additional inspection of ERR-4 values in ERR segments to determine whether the VXU was accepted or rejected; this guidance resolves that ambiguity by limiting use of 'AE' to cases with severity 'W' errors but no severity 'E' errors.

An MSA-1 value of 'AR' indicates the VXU was unsuccessful, that is, rejected. Previously, 'AR' was reserved for four use cases: an unsupported message type, an unsupported event code, an unsupported processing ID, and an inability to process the message for reasons unrelated to format or content. This guidance removes the last of these as a valid reason to return 'AR', since it describes a transport or connectivity issue rather than an application-level outcome. As with ACKs more generally, MSA-1 cannot be used to convey transport or connectivity issues.
